# 各租户菜单拖动排序与本租户导航联动

## 1. 审核摘要

- **用户问题**：平台菜单已经可以直接拖动，各租户「系统管理 → 菜单管理」仍需编辑排序号；表格顺序与左侧导航还可能被平台规则覆盖，无法按租户的实际使用习惯整理菜单。
- **完成后变化**：所有当前原型租户都能像平台一样拖动一级整组、二级组内排序及跨组移动；保存后本租户左侧导航同步调整，撤销、刷新和重开保持一致。
- **本次范围**：15 个租户的普通 menu、共享树表、同租户 Shell 导航与本地演示状态；平台 allMenu 继续提供平台默认规则。
- **明确不做**：不新增租户或页面权限，不扩展其他业务表格，不接真实后台或在本工作区实施生产代码。2026-09-26 房总追加授权完整推送及建立管理端工程 Issue；本次补齐交付文档、发布原型与工程交接，生产实现仍走正式工程流程。
- **需要房总拍板**：无。Q001 已关闭——平台后来再次调整时是否保留租户已自行调整的顺序。推荐按同级分组保留：某组被租户调过后整组保留租户顺序，未调整组继续跟平台；跨组移动只保留被移动项的父级。房总于 2026-09-26 回复“按照这个来”，已批准推荐方案。
- **AI 新提案**：均已由房总于 2026-09-26 批准。R006 的平台与租户优先级、R007 的旧设置接续及外部变更时防止旧撤销覆盖新设置。其余拖动交互直接继承已批准 060，在本次普通 menu 范围适用。

## 2. 用户问题与预期结果

### 2.1 用户与场景

租户管理者在「系统管理 → 菜单管理」整理常用入口。平台管理者已经能从手柄拖动，普通租户页面却仍以手工数字排序为主。

### 2.2 用户问题

逐项编辑数字不直观；只改变表格而未改变导航，会让用户误以为调整没有生效。平台已有本地配置时，现行导航计算会再次套用平台顺序，租户排序可能被覆盖。

### 2.3 完成后用户能感受到的变化

看着目标位置拖过去，左侧对应菜单随即换到相同位置；各租户保存自己的调整，回到该租户仍能看到调整结果。

### 2.4 成功信号

| ID | 可观察信号 | 判定方式 |
|---|---|---|
| O001 | 当前 15 个租户都能完成三类拖动 | 注册表逐租户核对 |
| O002 | 菜单表结构与导航可见投影一致 | 稳定身份、父级与同级相对顺序比较 |
| O003 | 租户 A 调整不改变租户 B 或平台定义 | 保存前后状态与导航对比 |
| O004 | 撤销、刷新、失败不产生表格与导航分叉 | 浏览器操作与本地状态核对 |

### 4.1 已发现冲突

1. 060 §3 明确不扩展普通 menu；本次 E001 明确要求扩大到所有租户普通 menu。本规格审核后在该范围覆盖旧排除项，060 的平台拖动合同继续有效。
2. 060 R009 及现行设计规范把平台顺序/父级无条件应用于全部租户。仅解锁普通菜单手柄仍不能保证实际导航跟随。R006 提议为租户明确调整建立局部优先级；这会形成旧规则的限定例外，Q001 已由房总批准，按本规格实施。
3. 051 及设计规范的普通菜单手工排序号将被同层自动顺序替代；编辑不再提供独立数字排序入口，避免两套顺序互相覆盖。
4. 现有普通表格模型、导航 override、平台投影不是同一棵有效树。新实现必须同时处理三者，不能只新增手柄或只发重绘通知。
5. 本轮已获 E010 完整推送授权，对 README/CLAUDE/设计规范、平台相关 PRD/流程和远端入口逐项收敛；明细见 source-convergence.md。既有已交付版本快照保持，只作各自历史范围证据，不能覆写。

## 5. 用户场景与验收

### US01 — 租户管理者直接整理本租户菜单

#### AC-R001-01 — 全租户入口与相同交互
- Given 注册表中的每个租户，进入系统管理的 menu。
- When 查看树表并打开编辑，再取消。
- Then 可编辑菜单名称左侧有独立手柄；保留原六列，排序列改为同层只读顺序；编辑提示由拖动调整，不再输入数字。名称、权限和行操作仍按普通菜单原有合同；bzds/menu 与 bzds/allMenu 不混用。

#### AC-R002-01 — 一级整组与二级两类移动
- Given 展开/收起一级、多个二级、空一级及有自身页面的一级。
- When 一级移到另一一级前后；二级在同组重排或移到另一一级的指定位置。
- Then 一级带全部子项且子项相对顺序不变；二级保留身份和字段，跨组只改归属与顺序；直落一级追加末尾，空一级成为首项，移空一级在库存保留。有自身页面的一级接收子项时仍保留其原页面入口，不丢页或重复路由。

#### AC-R003-01 — 表格与左侧导航即时一致
- Given 同租户 Shell 及另一同租户窗口已经打开，并有仍可见的当前业务页。
- When 完成移动或撤销。
- Then 所有同租户窗口的导航及时更新；可见菜单父级和同级顺序与菜单表的可见投影一致，无需整页刷新；仍可见的业务页、页签和输入状态保留。隐藏项留在完整库存，不因没有侧栏项而被删掉。

#### AC-R004-01 — 租户与身份隔离
- Given 租户 A/B、bzds/allMenu、现有同名不同路由菜单，以及异常重复路由 QA 样本（当前登记租户内路由并未重复）。
- When 在 A/menu 移动某个稳定身份的菜单。
- Then 只更新 A 的配置和导航；B 的本地配置与导航、平台定义保持不变。按租户和稳定菜单身份匹配，不按文字找项，不引入 A 原本没有的页面或权限。异常重复路由保留原数据，拒绝相关拖动并提示配置冲突，不在本轮新增重复入口/页签语义。

### US02 — 调整可以保存、撤回并兼容平台规则

#### AC-R005-01 — 保存、撤销与恢复
- Given 本租户已有菜单编辑结果。
- When 完成一次移动、撤销、刷新或关闭重开。
- Then 表格与导航均读取同一成功状态；有效移动只有一条旧/新父级与位置记录，撤销有自己的记录。撤销仅回退最近一次移动且同时恢复该次覆盖标记；刷新或后续菜单数据修改后撤销失效，展开/滚动/打开后取消弹窗不清除。旧显示、权限和名称配置保留。

#### AC-R005-02 — 写入失败不传播半成品
- Given 菜单树保存或相关导航本地状态写入失败，包括多步写入的后一步失败。
- When 提交移动或撤销。
- Then 表格、导航、覆盖信息与记录都保持上次成功结果；不出现假成功或其他窗口的半成品。提示未保存与重试；撤销失败保留重试机会。

#### AC-R006-01 — 平台已有设置后再调租户
- Given 平台已有保存的排序/归属，A 尚无本轮明确调整。
- When 打开 A/menu，再调整其中一组顺序或一个二级的归属。
- Then 初始表格与导航使用当前有效规则；成功后 A 导航按本轮移动结果显示，不再被旧平台顺序弹回；B 继续按平台规则。平台隐藏和原有权限边界始终有效。

#### AC-R006-02 — 平台后来再改时的推荐优先级
- Given Q001 批准推荐方案，A 已调一级顺序、组 X 的二级顺序或菜单 a 的父级，B 未调。
- When 平台后来改变一级/组 X/组 Y 顺序或菜单 a/b 的父级，或隐藏菜单及父级。
- Then A 已明确调整的同级列表顺序和 a 的父级保留；未调整的组 Y 顺序及 b 的父级继续跟平台；B 全部跟平台。平台隐藏继续生效，租户拖动不能解除隐藏或获得新页面权限。新增有效项不丢失，按 R006 确定性放置，表格和导航一致。Q001 已批准此优先级。

#### AC-R007-01 — 旧配置与并发变更
- Given 旧版数字排序/隐藏/权限、本地平台设置，或另一同租户窗口正在修改。
- When 首次载入新版，或拖动中、可撤销时接到外部菜单变更。
- Then 无新版覆盖时保留升级前有效导航，不把旧重复数字误解成新版拖动意图，不清空旧字段。外部变更使进行中拖动取消、旧撤销失效，重新载入最新结构并提示，不用旧快照覆盖新设置；相同 row.id 在不同租户下不串用。

#### AC-R006-03 — 跨组不绕过平台隐藏及失效父级恢复
- Given 平台将 a 归于 X，租户把 a 移到 Y，或已保存的租户目标父级后来失效。
- When 平台隐藏 X 或 a；或目标 Y 不再存在；随后平台恢复对应配置并刷新。
- Then 平台当前祖先链作为独立可见性条件：即使租户已把 a 移出 X，平台隐藏 X 仍抑制 a，恢复显示后再按租户有效结构展示。无效目标覆盖保留但暂不应用，回退当前平台有效父级（无平台定义时用本租户原始有效父级）并提示；目标重新有效后覆盖恢复应用。覆盖不能复活已被平台删除的页面。

### US03 — 拖动边界与可操作性完整

#### AC-R008-01 — 非法落点和取消
- Given 正在拖动或菜单含历史三级分支。
- When 尝试一级嵌套、二级升一级/生成三级、循环归属、无效身份、原位、表外松手、Escape、失焦或 pointercancel。
- Then 非法动作说明原因；取消/无变化不保存、不写记录、不更新导航；恢复临时展开与焦点。历史深层分支完整保留且相关拖动禁用，不拍平。

#### AC-R009-01 — 长表、键盘与禁用状态
- Given 长表、窄窗、收起目标、手柄焦点、加载/错误/空态或不可编辑菜单。
- When 用指针拖至边缘或悬停收起一级，或用 Space/Enter、方向键、Enter/Escape 移动。
- Then 复用 060 的插入线、文字目标、分支拖影、悬停展开、自动滚动与键盘/桌面触控；表头冻结与行操作、弹窗保持可用。未加载、空态、错误或不可编辑时不能拖动；空态不造菜单，错误可重试。操作手柄不抢占展开和行操作。

### 6.1 不变量

- INV001：移动前后本租户稳定菜单身份集合相同，无丢失、重复或循环。
- INV002：一级整体移动不改变其子项相对顺序和业务字段。
- INV003：可见导航是本租户有效完整菜单树的受限投影，父级与顺序不能另外计算出不同结果。
- INV004：取消、无变化、失败后已保存树、覆盖与导航保持上次成功值。
- INV005：本租户操作不改变平台定义、其他租户配置、权限或业务数据。

### 6.2 默认值与配置

无额外排序模式或保存按钮；从手柄直接操作。同层顺序按完整库存自动显示 1…N，隐藏/收起不造成重新排序。交互阈值复用 060：约 6px 启动、600ms 悬停展开、40px 边缘滚动区；不新增业务配置项。租户后续优先级依已批准 Q001 与 R006 执行。

### 7.3 进入、退出与恢复

入口是 Shell 的各租户「系统管理 → 菜单管理」。成功后展开目标并让移动项可见；离页/刷新终止未提交动作。刷新恢复成功结构、折叠/滚动状态并清会话撤销。仅折叠、滚动、打开后取消编辑不改变菜单数据。无服务器离线/重试状态，存储失败使用本地失败路径；既有删除确认继续保留，拖动本身不增加破坏性确认弹窗。

## 8. 数据、权限与隐私

### 8.1 展示数据

沿用当前各租户脱敏菜单样本和有效本地编辑。树行用 tenant+route+row.id，导航关联用既有稳定 key/平台身份及原始路由；当前租户内 key/route 无重复，但存在同名项。异常重复路由仅作为 QA 样本，保留原数据并拒绝相关拖动，不扩大 Shell 的入口/页签语义。普通 menu 的 tree.key/parentKey 与平台的 parentId 字段差异由适配处理；同名、旧重复排序号、隐藏项都必须保留。顺序 1…N 是原型自动生成，不伪称真实采集数据，也不能沿用旧 order 降序比较而反转导航。

平台调整可能为本租户现有页面派生新的父容器；普通菜单树须显示该有效容器并提供稳定定位，不按同名回填到旧分组。容器仅整理已有页面，不引入其他租户库存。平台删除或隐藏的条目不得因租户覆盖仍含旧 key 而复活；不存在的覆盖成员不参与展示。旧“恢复本页初始样本”沿用自身原有重置范围，本轮不增加含义不同的“恢复平台顺序”入口。

### 8.2 权限

能编辑的菜单可拖动；只读、disabled、editable=false 或无编辑操作的行不可拖。排序只改变呈现和归属，不修改超级权限或显示状态，不绕过平台隐藏，不虚构服务器授权校验。

### 8.3 隐私与租户隔离

浏览器本地演示，按租户隔离；同源同浏览器窗口联动不代表服务端共享存储或跨设备同步。验收用独立 QA 存储，不清除用户已有浏览器设置。不读取真实后台、不上传任何本地原始资料。
