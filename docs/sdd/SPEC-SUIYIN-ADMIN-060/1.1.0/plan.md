## 5. 信息结构

保持原九列表格和顶部操作。名称左侧增加手柄，排序列显示自动同层顺序。标题下放一行轻提示及有效时出现的撤销；第一列保持可访问，横向滚动仍可拖。移动中显示菜单名称/二级数、目标父级和位置，并在目标表行边缘显示插入线。

## 6. 交互实现

Pointer Events 从独立手柄发起；6px 阈值避免误触，拖动使用临时目标，不在 move 事件中修改模型。一级以完整分支为单位定位，二级只在一级下的槽位插入。临时展开只更新行可见性，保留 pointer capture。约 600ms 悬停展开，动画帧驱动上下边缘滚动。键盘共享同一目标/提交模型。提交使用本地事务快照，失败还原，成功提供一次撤销；后续实际菜单修改使撤销失效。

2026-09-21 刷新反馈修复：继续使用原有 tenant+route 数据键，增加独立的树表/侧栏视图键，恢复折叠、滚动、页签和侧栏收起状态。平台菜单显示本地保存/恢复提示，编辑隐藏值写入失败时回滚并保留表单重试。普通菜单更新只重绘导航，原始导航快照独立保留，支持隐藏后重新显示，不再整页重载。此为 1.0.0 刷新修复记录。1.1.0 按 E008 接入平台定义到全租户侧栏，拖动仍不扩展到普通 menu。

## 7. Mock 方案

1.1.0 实施差异：按 E008 用已保存 bzds/allMenu 作为唯一平台状态源，不另写全租户副本。Shell 加载平台基线以匹配稳定 ID；有路由的项精确匹配，无路由分组由其原始子路由归属匹配，禁止单靠名称。投影仅使用租户既有可用叶子入口，按平台父级重组、按列表顺序排序并叠加平台隐藏；未匹配的新样本项保留原库存。若二级移入有独立页面的一级，该一级以分组呈现并保留其原页面入口，避免丢失页面。成功写入后同窗通知，其他窗口通过 storage 事件更新；失败不通知、不改变已保存导航。旧本地配置直接接续。此项替代第 6 节历史修复中“不将 allMenu 自动同步”的说明。

默认使用现有 22 一级/80 二级和既有本地覆盖。验证采用独立浏览器上下文、qa=1 前缀，构造空一级、三级、同名项、只读项和存储失败。不读写日常原型存储，不复制截图到公开资源。

刷新回归另外在独立 Chrome 上下文访问用户提供的完整地址，不带 qa 参数，验证日常数据键的保存、刷新与重新开页。该上下文与用户 Chrome 配置分离，不清理用户已有设置。

## 9. 风险与回退

共用树表和保存函数需保持其他路由原行为；拖动样式和控制器按 bzds/allMenu 激活。视图恢复复用 menu/allMenu 和 Shell 的既有状态约定。旧深层分支保留并禁用相关拖放。旧 localStorage 不清空、不提高源样本版本。回退只撤销本轮五个源文件中的对应改动，不覆盖其他任务文件。
