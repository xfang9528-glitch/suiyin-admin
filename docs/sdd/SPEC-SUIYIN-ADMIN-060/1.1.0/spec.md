# 平台菜单拖动排序与二级菜单跨组移动

## 1. 审核摘要

- **用户问题**：平台菜单多时，逐条修改排序号很难把菜单放到想要的位置，也无法直观整理一级和二级归属。
- **完成后变化**：拖一级带着全部二级一起移动；二级既能在组内排序，也能直接拖到另一个一级下。
- **本次范围**：截图对应「平台菜单管理」allMenu 静态树表及所有租户侧栏联动，延续九列、展开收起、固定表头和行操作。
- **全租户联动**：平台列表是所有租户侧栏的统一排序、归属和显示规则；保存、撤销后即时更新已打开侧栏，刷新和切换租户继续生效。用户 2026-09-21 明确纠正前版不联动的错误理解。
- **明确不做**：不扩展拖动到普通 menu 或其他列表；不赋予租户原本没有的页面入口，不执行同步/复制批量操作，不修改真实后台。
- **需要房总拍板**：无；2026-09-21 房总明确“按这个做”，Q001 已关闭。
- **AI 新提案**：左侧拖动手柄；排序号自动生成；一级不降级、二级不升为一级或生成三级；落点提示、悬停展开和边缘滚动；落下即本地保存并可撤销上次移动；键盘等价操作。见 R001、R004–R008。

## 2. 用户问题与预期结果

### 2.1 用户与场景

用户为维护平台菜单的管理者。截图里「数据展示」下有大量二级菜单，现通过编辑菜单的排序数字调整位置，需要反复查找和比较。

### 2.2 用户问题

数字不能直接表达要放在某菜单前、后或另一个分组内；长表下反复修改和核对成本高，一级与子项容易被错误拆开。

### 2.3 完成后用户能感受到的变化

看着目标位置直接拖过去，一级整组移动，二级跨组移动后立即显示在新归属下，不必计算排序号。

### 2.4 成功信号

| ID | 可观察信号 | 判定方式 |
|---|---|---|
| O001 | 三类移动都无需输入数字或打开编辑弹窗 | Chrome 实际操作 |
| O002 | 移动前后菜单身份集合相同，一级子项不丢失 | 比较树结构与稳定 ID |
| O003 | 长列表可跨屏移动，刷新可读回，误拖可撤销 | Chrome 实际操作及本地状态核对 |

## 3. 范围

### 3.1 In Scope

现有 allMenu 的一级重排、二级同组重排和二级跨一级移动；拖动反馈、取消、撤销、长表滚动、键盘入口、本地保存与回读。排序列调整为自动计算的只读顺序，编辑/新增里的数字不再承担人工排序入口；新菜单默认追加到所属层级末尾。

### 4.1 已发现冲突

0. E008 明确替代 1.0.0 的 R007/INV005 及“不联动侧栏”的范围推断。现行设计规范“隐藏、排序只影响本租户”仍适用于租户菜单配置，不适用于平台 allMenu 的统一规则。本轮先修订本地 SPEC/Plan 并实施；全套设计文档与旧远端快照在明确完整推送时收敛。

1. 051 §7、§11 和现行设计规范保留手工数字排序。E001 要求改为拖动；本规格仅在 allMenu 范围以自动顺序替代人工输入，普通 menu 保留旧合同。此变化及具体呈现纳入 Q001。
2. 当前平台编辑父级选择可以选到二级。此次新增拖动只覆盖一级/二级，不把旧编辑能力推断为允许拖出三级；已有更深层本地分支应完整保留，涉及该分支的拖动暂禁用并说明原因，不静默拍平。现有父级编辑能力不在本次扩大或重构范围内。
3. 旧资料描述按真实后台保真；本次拖动属于用户新增需求，不声称真实后台已支持。原始截图和采样仍是历史证据。
4. 若后续明确「完整推送」，需更新当前设计说明中 allMenu 的排序入口，并将旧版本快照标为历史；本轮未获发布指令，不改完整 PRD/设计规范、不改远端 SDD。

## 5. 用户场景与验收

### US01 — 直接整理菜单位置

#### AC-R001-01 — 不再填写排序号
- Given allMenu 已加载且可编辑。
- When 用户查看树表、编辑菜单或新增菜单。
- Then 名称左侧有独立手柄，顺序为同层从上到下的只读 1…N；编辑不再要求填写排序号，新项追加到所属层级末尾；点展开、文本和行操作不会误触拖动。

#### AC-R002-01 — 一级连带全部二级移动
- Given 一级 A 有多个二级，分别在展开和收起状态下验证。
- When 将 A 拖到另一一级 B 的前方或后方。
- Then A 与全部子项作为整体移动，子项 ID、归属、相对顺序和字段不变；落点在 B 的完整分支前或后，不插进 B 的二级中。

#### AC-R003-01 — 二级组内与跨组移动
- Given 一级 A 内的二级 x，以及一级 B（分别验证有子项、空一级和收起状态）。
- When x 在 A 内重排，或拖至 B 内某二级前/后，或拖到 B 的接收区域。
- Then x 保持二级；组内只改顺序，跨组改为 B 的子项并放在指定位置；直接落在 B 上则追加末尾，空 B 则成为首个子项。A、B 的展开箭头与子项数量随结果更新，A 移空后保留一级行。

#### AC-R004-01 — 非法落点和取消
- Given 正在拖动一级或二级，或遇到已有三级的本地分支。
- When 试图让一级嵌套、二级成为一级/三级、放回原位、落在表外、按 Escape、窗口失焦或发生 pointercancel。
- Then 非法落点显示原因，取消/无变化不改树、不写保存或操作记录；涉及已有更深层分支的拖动禁用，保留原数据。取消后还原临时展开状态，焦点回手柄。

### US02 — 长列表移动清楚且可恢复

#### AC-R005-01 — 跨屏与目标预览
- Given 超过一屏且横向溢出的菜单表。
- When 拖到上下边缘、悬停收起一级、在一级前后和组内落点间移动。
- Then 表格纵向自动滚动；悬停目标约 600ms 后展开；插入线和文字说明准确显示最终父级及位置。一级拖影显示携带子项数量；固定表头、横向对齐、操作列、浮层继续可用，手柄与目标提示在横向滚动时仍可访问。

#### AC-R006-01 — 保存、撤销与刷新
- Given 页面已有其他本地菜单改动。
- When 完成移动、撤销上次移动或刷新重开。
- Then 移动和撤销分别保存到当前 tenant+route 本地状态；刷新按已保存结构回读，原有改动不丢失；每次有效移动只记一条含旧/新父级与位置的记录。撤销恢复最近一次移动前的结构，并只在下次菜单数据修改或刷新前有效；展开/滚动不清除撤销。

#### AC-R006-02 — 本地保存失败
- Given 浏览器本地存储写入失败。
- When 用户提交移动或撤销。
- Then 恢复提交前的树、序号与操作记录，不显示成功；提示未保存、顺序已恢复，可以重新拖动。撤销写入失败时保留撤销入口以供重试。

#### AC-R007-01 — 作用范围与身份
- Given bzds/allMenu、普通 menu 页和另一租户的本地数据。
- When 移动两个同名但不同 ID 的菜单，刷新并打开其他页面。
- Then 仅指定 ID 的菜单移动，名称、路由、显示/隐藏、权限和其他字段不变；所有租户侧栏按平台顺序及父级显示各自可用菜单，其他租户配置存储和业务数据不变，不执行批量按钮或真实后台写入。

#### AC-R009-01 — 全租户即时联动及刷新恢复
- Given 已打开 bzds 平台菜单和其他租户窗口，部分租户拥有同名但路由不同的菜单。
- When 调整一级顺序、二级排序/跨组，或隐藏/显示平台一级/二级，或撤销移动。
- Then 当前及已打开其他租户侧栏无需整页刷新即时变化；切换租户、刷新重开后保持。隐藏一级同时隐藏其当前子项，重新显示恢复对应入口。同名不同路由分别匹配；不新增租户原本没有的页面权限，不覆盖本租户独立隐藏或其他业务配置。

#### AC-R009-02 — 旧设置接续与失败边界
- Given 本浏览器已有前版保存的 allMenu 排序/隐藏状态，或写入失败。
- When 加载新版，或提交失败操作。
- Then 已保存状态直接用于所有租户侧栏，无需重新拖动；失败时侧栏及其他租户保持最后一次成功值。侧栏重绘保留仍可见的当前页及页面状态。

#### AC-R008-01 — 键盘与可操作状态
- Given 手柄获得键盘焦点，或页面处于载入中、错误、无数据或既有不可编辑状态。
- When 使用 Space/Enter 进入移动、上下键切换当前父级下的插入位置、左右键切换相邻一级作为二级的新归属，Enter 提交、Escape 取消。
- Then 可完成与鼠标相同的三类移动，读出菜单、目标父级和位置，焦点随目标滚入可见区；一级不支持切换父级。不可编辑/未加载时不允许拖动；空表不造菜单，错误保留重试。桌面触控可从手柄执行相同规则。

### 6.1 不变量

- INV001：每次移动前后稳定 ID 集合完全相同，无丢失、重复或循环归属。
- INV002：一级移动时其所有二级仍属于原一级，且相对顺序相同。
- INV003：二级跨组只改变自己的父级与位置，不连带改变其他菜单的业务字段。
- INV004：取消或保存失败后，已保存结构与提交前相同。
- INV005：一次操作仅写同一份 bzds/allMenu 本地状态；所有租户侧栏派生读取，无线上写入，不逐租户复制/覆盖业务数据。

### 6.2 默认值与配置

初始显示顺序保留当前有效本地结构；只读序号据当前同层顺序生成。默认不切换额外“排序模式”，从手柄直接拖。悬停展开约 600ms，指针位移达到约 6px 后才启动拖动，边缘热区约 40px；三项为可在预览中微调的 AI 呈现建议，不作为新增业务配置项。拖动同一原位置为无操作。

### 7.3 进入、退出与恢复

入口为现有 Shell 的平台菜单管理。取消只撤销当前未提交移动，恢复临时展开状态；成功后保持目标一级展开并让移入项可见。切走页面/关闭页签/失焦终止未落下的移动。刷新恢复已保存树，清除会话撤销入口。任意编辑、增删或平台操作实际改变菜单数据后，清除上次拖动撤销，避免覆盖后续更改；单纯打开并取消弹窗不清除。拖动期间不能并行编辑其他菜单。

### 7.4 文案合同

| 场景 | 文案 | 为什么这样写 | 禁止写法 |
|---|---|---|---|

| 跨组预览 | 移入「目标一级」· 放在「目标菜单」前 / 末尾 | 说明实际位置 | 仅用颜色表达 |

| 撤销 | 撤销上次移动 | 范围明确 | 撤销全部修改 |
| 失败 | 未能保存，菜单顺序已恢复，请重试 | 说明结果与恢复动作 | 修改成功 |
