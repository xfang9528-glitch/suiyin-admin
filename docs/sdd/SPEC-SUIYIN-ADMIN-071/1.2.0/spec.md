# 按部门与账号配置每日回访选中及排除规则

## 1. 审核摘要

- **用户问题**：运营每天重复找当天应该回访的人；不同部门、工作号和回访目的需要不同组合，逐次定制规则难以维护。
- **完成后变化**：管理者复用群发的账号选择、选中与排除维度，保存一套可重复使用的规则，另行启用并设每日运行时间；到回访日按当天数据筛出好友，有该好友所属账号接待权限的销售在自己的回访列表看到该好友，无权限的销售看不到。
- **本次范围**：已按E021将深圳1.1.0能力补到其余五个现有艺星租户，并完成六租户静态验证。沿用一条规则多个节点、21项选中/26项排除、节点条件复制、每日时间及启停；账号、选项、规则与存储按tenant隔离，非艺星不增加。房总随后以E022授权1.2.0完整推送；PC名单界面仍另期实施。
- **明确不做**：真实定时运行、私聊数据接入原型、PC 名单改造、自动发送、AI 个性化内容、分配机制和执行质检；这些作为后续切片，不把“已保存规则”说成“已生成真实名单”。
- **需要房总拍板**：E021已批准六艺星范围，E022另行授权本次完整推送，无新增阻塞决定。Q002–Q004继续原型默认值，Q005产品映射延期；远端、部署和通知完成仍须实际回执。
- **AI 新提案**：没有新增业务提案；E021仅扩展明确的艺星租户范围。共享设置、节点到期与条件复制继续R004/R015；缺少本租户实体来源时使用明确标注且独立的合成示例或空态，不把深圳账号/客户/医生等实体作为其他租户事实。

## 2. 用户问题与预期结果

### 2.1 用户与场景

- 管理者：按业务目的、账号所属部门/群组（渠道）和工作号配置规则，不必每次请人另写一套定制条件。部门在本规格中表示账号群组归属，不表示规则使用人员范围。
- 咨询师：后续上班在 PC 看到自己有接待权限账号下的应回访好友和入选原因，不再每天手工拼相同筛选；无该账号接待权限时看不到其应回访好友。
- 深圳实例：添加好友后按固定节点激活；近期已有联系时跳过本次；按产品决定后续沟通方向。
- 看图纠正：添加后回访作为一条规则，第3/5/7天是规则内节点；复用和独立编辑发生在节点条件层，不能将每个节点拆成顶层规则。节点列表不硬编码。

### 2.2 用户问题

一次群发通常处理当时筛出的名单。回访则需要每天重新回答“今天该找谁”，不能把配置当天的人保存成永久名单，也不能因中途聊天就错移固定添加周期。

### 2.3 完成后用户能感受到的变化

能看懂、检查、调整并重复使用一套选人规则；明确哪几个部门、哪些账号、哪些人会被选中或排除、下一次何时运行。

## 3. 范围

### 3.1 In Scope

- 管理页规则列表、新建/编辑、规则内节点列表及编辑、节点条件复制、共同范围、两组筛选、日期表达、运行设置、摘要、保存/启停。
- 生效范围合并为一处账号选择，沿用群发“部门/群组（渠道） → 工作号”的操作；按群组选择或指定账号。不同渠道可以分别配置选中、排除和运行设置，不再单列咨询师使用部门。
- 同租户继承群发选中和排除维度，保留普通/艺星差异；不把医美维度强加给其他业态。
- 六个现有艺星租户的规则页与各自独立的合成示例。深圳保留原有规则与本地状态；新补成都、北京、广州、杭州、嘉兴五个入口。可选“按今天试算”明确标为本地示例，不将深圳访谈参数当作其他门店已批准的实际运营方案。
- 六个租户各自菜单管理同步对应入口；复用德三平台已有revisitRules稳定定义一次，不新增同义路由、不扩展非艺星租户、不改群发叶子页面。
- 锁定后续PC可见性：应回访好友按所属工作账号接待权限进入销售回访列表；本轮只定义并验收合同，不扩展为PC页面实施。

### 3.2 Out of Scope

- Flutter / React / Go 等生产端实现、真实调度、数据库、共享规则、登录和写 API。
- PC 每日名单实施、回访话术生成、自动发送、执行质检、归属重分配和跨账号客户合并。
- 既有群发本体修改、真实生产发布、Issue创建及开发进度表；非艺星入口扩展。E021日常补齐阶段未授权发布；现由E022单独授权1.2.0静态文档、单文件、版本化SDD与原型仓完整推送。已发布1.1.0包和history/1.1.0保持不变，不以E020替代本次授权。

## 5. 用户场景与验收

### US01 — 管理者组合一套可复用规则

- 用户：有规则管理权限的管理员。前置：当前租户及可管理范围已明确。目标：按账号所属群组或指定账号配置选中和排除，独立价值是不同渠道可使用不同回访规则。

#### AC-R001-01 — 按账号群组配置不同渠道规则
- Given 演示账号甲属于渠道A，账号乙属于渠道B；管理者为两组分别保存不同筛选条件的规则。
- When 查看账号选择和两条规则摘要。
- Then 以同一“部门/群组（渠道） → 工作号”控件表达范围，两条规则各自作用于所选账号群组；可选择群组或指定其中部分账号；不存在另一个“供哪些咨询师部门使用”的字段。

#### AC-R002-01 — 两侧维度完整继承
- Given 在艺星演示租户新建规则。
- When 展开选中与排除条件。
- Then 与§6.3清单逐项一致，21项选中与26项排除均有对应入口；其他租户不硬套医美选项。

#### AC-R003-01 — 选中全部满足、排除任一命中
- Given 选中要求等级A与某需求，排除要求我方2天或对方2天有消息。
- When 对合成好友判断。
- Then 等级与需求必须同时命中；任一方向近期有消息均排除；已排除对象不被其他选中条件加回。

#### AC-R004-01 — 日期随回访日计算
- Given 添加日设为第0天，一条“添加好友后回访”规则有第3天节点A、第5天节点B，合成好友添加日为9月24日。
- When 分别试算9月27日、28日、29日。
- Then 到期命中依次为节点A、无、节点B；顶层始终一条规则。各节点到期后独立应用自身条件，不依赖前一节点完成，不因消息改变添加锚点。节点时点只配置一次，不能再让用户重复填写同一添加天数。第0天口径为Q002原型默认。

#### AC-R005-01 — 深圳实例任一方消息排除
- Given 好友今天处于第5天节点，近期仅对方发过消息，我方没发。
- When 运行示例判断。
- Then 今天排除；同理仅我方发过也排除；日后仍按原添加日期计算第7天节点，不重开周期。

#### AC-R009-01 — 账号选择与搜索不越界
- Given 已在渠道甲选账号1，又搜索当前渠道的账号2。
- When 对搜索结果全选或清空搜索。
- Then 搜索批量动作只影响当前可见结果，原先选择保留；所在账号的选中/排除条件均不得扩到规则范围外；账号选项不串租户。

### US02 — 保存后决定启用与运行时间

#### AC-R006-01 — 保存与启用分离
- Given 合法规则选择每天01:00、上海时区。
- When 仅保存，随后单独启用。
- Then 先处于未启用；启用后显示下一次计划时间；当前时间已过01:00时计划为次日，不补跑今日。页面同时标明仅本地演示。

#### AC-R007-01 — 编辑、取消与失败
- Given 已启用规则正在编辑。
- When 取消或模拟保存失败。
- Then 原已保存版本与启用状态保持，失败可重试；成功保存才替换规则版本，并从下一次计划运行使用新版本。重复提交不新增重复规则。

#### AC-R008-01 — 零命中不阻止保存
- Given 规则配置合法、今天示例数据命中0人。
- When 保存或查看试算。
- Then 允许保存；明确显示0人，不要求手工勾选一名好友；加载失败、无权限和字段未知不得显示为0人。

### US03 — 不因复用规则扩大权限或制造能力承诺

#### AC-R010-01 — 缺失数据不等于未联系
- Given 最近消息数据缺失，或指定账号权限已失效。
- When 预览命中与启用资格。
- Then 缺失数据标“无法判断”，失效范围明确提示并阻止带失效配置启用；不当成无消息，也不自动切成全部账号。

#### AC-R011-01 — 摘要可核对
- Given 配置账号群组/指定账号、添加节点及两条消息排除。
- When 查看摘要与示例试算。
- Then 摘要逐项呈现范围、节点、排除、运行时间及状态；示例显示入选/排除理由和试算基准时刻，不冒称真实人数。

#### AC-R012-01 — 配置和执行边界
- Given 管理页已在本地保存并启用示例规则。
- When 查看结果和未来日期。
- Then 不发消息、不调用真实调度；未来不显示已经确定的好友名单；规则不自动重新分配客户或改变部门成员可见权限。

#### AC-R013-01 — 租户与旧功能不串用
- Given 六个艺星租户和非艺星租户分别进入各自管理页；旧群发仍在其原入口。
- When 切换租户、展开字段或打开旧群发。
- Then 六个艺星均可进入本租户回访规则，部门、账号、选项、规则状态按tenant隔离；非艺星没有新增回访规则入口，也不能通过直接路由获得艺星演示；旧群发行为和零选人守卫保持。

#### AC-R013-02 — 六租户菜单完整且平台定义唯一
- Given 已有深圳revisitRules和德三allMenu唯一平台定义，其余五个艺星尚缺入口。
- When 逐一查看六租户左侧聊天管理及各自系统管理的菜单管理，并核对德三平台菜单。
- Then 六租户各有且仅有一个回访规则入口，稳定route/key为revisitRules；新增五租户使用本租户现有聊天父级。德三平台定义只保留一份，不向非艺星自动分发；原有名称、排序、隐藏、删除及权限调整不因新增入口被重置。

#### AC-R013-03 — 规则与演示实体按租户隔离
- Given 深圳已有本地保存规则，在另一艺星租户创建并启用一条规则、复制某节点条件。
- When 在六租户间切换并刷新，查看所在账号、选项及示例试算。
- Then 仅当前tenant的规则、启停、实体选项、合成好友及结果可见，深圳原数据不变；每页仍有21项选中/26项排除及一规则多节点行为。没有本租户来源的实体明确标合成或空态，不借用深圳真实/示例实体作为本租户来源；跨tenant账号ID不能扩大当前权限或命中其他租户好友。

#### AC-R014-01 — 销售只看到有账号接待权限的应回访好友
- Given 工作账号甲和乙均筛出应回访好友；销售A只有甲的接待权限，销售B只有乙的接待权限，销售C有甲乙两个账号的接待权限。
- When 各销售查看回访列表。
- Then A只看到甲下的应回访好友，B只看到乙下的应回访好友，C看到甲乙两者；同一规则选中两个账号也不扩大A或B权限。A失去甲权限后，后续展示/读取不得继续向A返回甲下好友；生成时曾有权限不构成后续访问授权。若同一联系人同时存在于两个账号下，有甲权限不能借此读取乙下的回访对象。

### US04 — 同一规则内复制节点筛选，不同节点独立编辑

- 用户：管理者。前置：同一规则已有第3天及第5天节点。目标：在第5天复用第3天的筛选，再独立调整，顶层列表仍只显示一条回访规则。

#### AC-R015-01 — 复制条件不改变目标节点时点
- Given 一条规则每天01:00运行，节点A为添加后第3天，节点B为第5天；A排除近2天我方或对方消息。
- When 在B选择“复制其他节点条件 → 第3天”，再把B的排除天数改成3天。
- Then B仍为第5天，A仍为第3天/排除2天；节点条件各自独立。复制不更改共同账号范围、回访基准、运行时间、启停或节点身份，不创建顶层规则。3天排除只为演示独立性，不代表深圳实际实践。

#### AC-R015-02 — 复制覆盖、取消与提交边界
- Given 目标节点已有筛选条件，管理者发起复制。
- When 查看替换范围，选择取消或替换，随后保存或放弃整条规则。
- Then 明示仅替换目标节点选中和排除，不改时间点；取消复制不改草稿，确认替换只改当前草稿，放弃整条编辑恢复已保存内容。整条保存成功才生效，重复保存不产生重复规则/节点。任何复制不携带结果、执行记录或权限。

#### AC-R015-03 — 节点及规则层级可见
- Given 规则包含第3、5、7天三个节点。
- When 在列表、规则详情及某节点编辑之间切换。
- Then 顶层仅一条规则，摘要显示三个节点；规则中可新增节点、编辑天数和条件、移除节点。至少保留一个合法节点，节点按天数排序，同一基准下不允许重复天数。删节点只改草稿并可通过取消整条编辑恢复。

### 6.1 不变量

- INV001：规则存条件；每日结果是基于回访日的数据，不是配置时的固定人名快照。
- INV002：候选好友始终受租户及工作账号权限限制；选账号群组不授予新的权限，也不定义任务分配给哪些员工。
- INV003：排除优先于选中；未知数据不被静默解释为“不满足排除”。
- INV004：固定添加日期锚点不因近期有消息变化；近期消息仅决定是否跳过本次节点。
- INV005：所有本地成功提示只说明原型效果，不能声称生产规则已运行。
- INV006：销售可见回访集合=已筛出的应回访好友集合∩该销售有接待权限的账号下好友集合；同规则、同账号群组或同名联系人均不能绕过此限制。
- INV007（提案）：节点复制复用条件，不共享后续修改、不改变目标时间点；节点“第几天”与整条规则“每天几点筛选”独立。

### 6.4 一条规则与多个时间节点（E016纠正；E018批准）

列表显示“添加好友后回访”一条记录，概览账号范围、第3/5/7天等节点、每日运行时间与启停。进入整条规则后，顶部设置名称/目的、账号范围、回访基准、每日运行时间，下面按天数列出节点及各自条件摘要。进入节点只编辑第几天、选中、排除及可选说明，群发21/26项维度完整保留。

共享账号范围适用于所有节点；节点可通过所在账号条件进一步缩小范围，不得扩大范围。不同渠道可分别建规则，各自包含一套节点。同一规则内不额外引入节点账号覆盖、单独运行时间或启停，以免共享与覆盖关系复杂。

节点时间是到期条件的唯一来源。规则基准选择添加日期时，第5天无需在选中区再配置一次添加后5天。若另加添加日期固定范围或其他日期约束，明确显示它是附加条件，和节点时间一起满足；复制只复制这些附加筛选，不复制节点时点或悄悄改日期值。

复用示例：在第5天节点点“复制其他节点条件”，选择第3天；展示“仅替换选中和排除，第5天不变”，确认后进入第5天草稿。调整第5天不会影响第3天。新增节点先填时间，再可复制已有条件；全部变更随整条规则保存/取消，已启用规则下次运行使用新版本。

节点是各自到期的检查点，不是依次完成的任务流程。第3天因近期消息被排除不取消第5天，第3天是否人工完成也不是第5天的自动前置。真实生成及跨规则重复回访治理仍按R012后续设计。

已有1.0.0本地规则不能仅因名称或配置相似就静默合并。1.1.0已实现按tenant的v2存储键，旧v1键只读保留；用户可查看旧规则、逐条显式导入新草稿，或明确开始新版示例。无法无损映射时说明原因，不猜测合并。1.2.0沿用该保护，六tenant隔离及深圳兼容已分别验证，不读取深圳存储作为其他租户初始状态。当前证据见checks/v1.2.0/，历史1.1.0与1.0.0记录仅作既有基线。
