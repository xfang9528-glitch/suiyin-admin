# 管理列表筛选表格及来源一致性

## 1. 审核摘要
- **用户问题**：销售使用统计暴露了通用实现与实际页面之间的差距，同样偏差也存在于整个管理后台。
- **完成后变化**：有来源的结构和交互按真实页面恢复，各租户来源透明，不用额外控件掩盖差异。
- **本次范围**：管理列表筛选表格及来源一致性；按源表单保留字段标签、日期初值、单选和复选结构；查询和重置依据真实动作，不普遍添加日期快捷项。 下拉选项以当前租户当前页面上下文为优先，不借用其他租户的实体选项；枚举与实体分开。 表格列的宽度、对齐、可排序属性以对应采样为准，保留空白列；分页及额外工具仅在来源要求时出现。 不向每个统计页自动插入汇总卡；来源说明直接区分本租户采样、参考样本与合成演示。
- **明确不做**：不修改线上和生产仓，静态原型发布按本轮“完整推送”授权，不将历史采集或DOM检查描述为当前线上逐像素一致。
- **需要房总拍板**：无；本次直接执行授权是“再按照这个逻辑把整个管理页都再对一遍哈，要保持一致”。
- **AI 新提案**：无新增业务；证据矩阵、专用渲染和来源提示为实现选择。

## 2. 用户问题与预期结果
评审者在相同租户页面对照筛选、表格、操作和内容。此前通用模板添加不存在的功能，削弱真实页面参照价值。
O001：所有登记入口完成证据分类，有硬证据的差异修复可追溯，缺少采集的地方有明确说明。

## 7. 状态与交互
有证据默认态→筛选草稿→查询结果；日期无效保留上一结果；缺少样本→说明；读取失败→重试；编辑取消→不保存；本地保存→可恢复。控件保留focus、禁用、溢出、键盘与关闭状态。实际视觉待浏览器复核。

## 8. 数据、权限与隐私
数据仅本地公开原型已脱敏样本；姓名沿用原已有员工名，客户和联系方式仍按公开包规则处理。来源指明本租户、参考租户或合成。导航和菜单可见性继续按既有本地权限规则。

## 9. 端与租户差异
只作用Admin。各租户保留菜单及字段差异，不把一个租户的采样下拉当作全局选项。
