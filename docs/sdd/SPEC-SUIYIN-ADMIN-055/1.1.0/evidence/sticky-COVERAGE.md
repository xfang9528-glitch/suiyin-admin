# 管理原型表头冻结验证（2026-09-20）

本次只新增 `prototype/admin-table-sticky.css` 和 `prototype/admin-table-sticky.js`，由内容入口共用。未更改业务数据、表格列宽、页面高度、既有滚动区或固定操作列。安装清单见 `install-manifest.json`；最终运行报告见 `sticky-runtime-report.json`。

## 覆盖实现来源

| 生成来源 | 表格/滚动方式 | 处理 |
| --- | --- | --- |
| `admin-content.js` | 通用列表、统计明细，`.table-wrap` 内滚动 | 原生 thead 整组冻结在本表滚动区内边缘 |
| `admin-sales-usage.js` | 多 tbody 销售分组，文档滚动 | 表头跟随文档可视区域，排序仍使用原事件 |
| `admin-sales-voice-stats.js` | 变声明细，`.voice-table-wrap` 内滚动 | 共享规则，不干扰变声筛选或底部合计 |
| `admin-ai-stats-aligned.js` | `.ai-table-scroll` 仅横向 overflow，文档纵向滚动 | 规避原生 sticky 被横向祖先拦截，横向列位置仍与表身相同 |
| `admin-new-added-records.js` | 固定可视高度的独立表区，当前深圳是已知零条 | 注册表头；空态不造行、不改高度 |
| `admin-menu-tree.js` | 树表及平台菜单表，表内双向滚动，原有右侧固定操作列 | 不更改横向固定；表头/固定列交点可点击且置于正文上方 |
| `admin-menu-tree.js` | 审计弹窗里的 table，`#dialogBody` 滚动 | 同一规则在弹窗内部边缘冻结 |
| `admin-sales-dashboard.js` | 页面中四张独立排行表 | 每张表的表头只在本表底部以内移动，不覆盖后面的卡片 |

所有使用 `<thead>` 的新增、重绘和重新插入表格由 MutationObserver 发现。仅监听 DOM 子节点，不监听自身 style；一帧内最多调度一次更新，ResizeObserver 只观察表格尺寸。表头整体平移，保留原节点、宽度、排序事件、可访问性与现有水平冻结列；多行表头作为整组移动，不采用固定行高或逐列硬编码。

富文本编辑器的可编辑正文不属于管理列表表头，且当前插入表格没有 thead，不对用户正文内容进行位置改写。历史未接入的 v1.0 独立 HTML 不在当前 `_shell.html → admin-content.html` 入口范围；根任务另做当前 752 个登记入口检查。

- 四排行表：当前每张只有短样本。滚动到 1070、1200、1450 后逐张验证表头底边不越过本表底边；前两张退出上方时表头也退出，不覆盖后两张。

- 多行表头：独立 DOM fixture 含两层表头、rowspan/colspan、两个嵌套滚动区；先滚内区再滚外区，整组表头保持在两区共同可视顶部，第二行没有覆盖第一行。
- 空闲稳定性：滚动停止后 250ms 内表头属性变化为 0，没有自身 MutationObserver/ResizeObserver 循环。
