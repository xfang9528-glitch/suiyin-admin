# 所有租户销售变声统计与菜单管理同步

## 1. 审核摘要

- **用户问题**：管理者想了解各销售使用变声的次数，现有销售使用统计仅展示消息数和聊天好友数，无法直接回答；新增统计菜单还容易漏掉菜单管理中的对应项。
- **完成后变化**：所有租户可在「数据展示 → 销售变声统计」按日期、部门查看每位销售的变声使用次数，并在菜单管理中控制同一个入口。
- **本次范围**：当前十五租户的静态管理页原型；独立二级菜单、统计页、菜单管理和平台定义同步；固化 DR-095。
- **明确不做**：不新增租户环境、不接真实后台或修改生产实现、不添加销售考核/效果归因；实施时未授权发布；2026-09-20后续“完整推送”已授权本次静态原型发布。
- **需要房总拍板**：无；Q001 已于 2026-09-20 随“按这个方案做”批准。
- **AI 新提案**：无未决提案；R003 已批准：独立任务首次成功生成计 1，同任务不重复计。

## 2. 用户问题与预期结果

### 2.1 用户与场景

- 用户：当前租户拥有统计查看权限的管理者。
- 场景：按单日或日期范围检查销售对变声功能的使用情况，并按部门缩小查看范围。
- 当前做法：销售使用统计能显示消息数和聊天好友数，未提供独立的销售变声次数。

### 2.2 用户问题

普通消息量无法代表变声使用量；侧栏新增入口若遗漏菜单管理，则配置与可见功能不一致。

### 2.3 可感知变化

管理者沿用熟悉的日期/部门查询方式，看到每位销售的变声次数，且能在菜单管理中找到并控制该统计入口。

### 4.1 已发现冲突

- 1.1.1：上轮将原型共享青绿主按钮当成真实销售使用统计规范，证据不足。按053纠偏基准和用户后台截图使用蓝色；数值右对齐、共享静态日历；该路由当前线上视觉仍待复核。旧1.1.0颜色对比证据只作历史。

- E009 替代 1.0.0 的单日/范围切换控件；统计仍支持同日与跨日，直接以起止日期表达。1.1.0曾将蓝色覆盖判断为偏差；该颜色判断已被E010的参照纠偏替代，日期直接区间决策继续有效。

- E002 明确取代 E001 中仅艺星的初始范围，采用全部十五租户。
- 现有销售使用统计采样保留单日/范围；泛用原型把第一个 radio 的 single 值当日期、快捷日期以采样日为基准，属于实现局限。新页按真实日期控件与运行当日实现，不继承空日期缺陷，不顺带修改旧页。
- 既有菜单快照不含新入口，是本次新增覆盖；保留其采集时间与来源，不把新菜单伪装成原站实采事实。
- 未发现既有变声统计计数合同；不能用普通消息数或聊天好友数推断变声次数。Q001 已批准采用首次成功生成口径。
- DR-093 控制变声能力资格与消息展示，本统计入口覆盖所有租户不会取代该资格门槛。

## 5. 用户场景与验收

### US01 — 管理者查看本租户销售变声使用情况

- **前置条件**：处于本租户原型，现有菜单/父级允许显示。
- **目标与独立价值**：查询某日或一段时间各销售的变声次数。

#### AC-R001-01 — 所有租户入口完整

- Given 十五个登记租户与默认菜单配置。
- When 分别展开数据展示并打开销售变声统计。
- Then 均到达独立的销售变声统计页面，租户品牌/人员/部门对应正确，原销售使用统计仍保留。

#### AC-R002-01 — 日期和部门查询

- Given 日期跨两天、两个部门和多名销售的本租户 Mock。
- When 直接选择开始和结束日期、部门并搜索，再依次选择今天/昨天/前天和重置。
- Then 查询仅含所选自然日范围及部门；快捷日按 Asia/Shanghai 运行当日计算；重置回开始/结束均为今天和全部授权部门，表格按销售/部门展示。

#### AC-R002-02 — 日期校验与全量导出

- Given 开始日期晚于结束日期或已得到多页查询结果。
- When 尝试查询非法日期，或对有效结果导出。
- Then 非法日期有明确错误且不覆盖上次结果；导出包含全部筛选结果及正确次数，不只导出当前页；取消选择不提交查询。

#### AC-R003-01 — 次数去重与归属（已批准）

- Given 销售甲有任务 A 首次生成成功及重复成功回调、任务 B 失败后重试成功、任务 C 始终失败，任务 A 被试听两次；销售乙有任务 D 成功。
- When 查询覆盖全部成功时间的日期范围。
- Then 甲为 2 次、乙为 1 次；按触发该任务的销售归属，不按当前接待人或声音模型归属，发送是否成功不改变“生成成功”这一计数。

#### AC-R003-02 — 跨日与零值（已批准）

- Given 任务在前一日触发、后一日首次成功；另一名本范围销售没有成功任务；一名销售使用多个工作账号。
- When 分别查询两天和合并范围。
- Then 该任务只计入首次成功的自然日；确定没有成功任务的销售显示 0，多工作账号按稳定销售身份汇总；部门取事件发生时归属，避免转组后改写历史。

### US02 — 管理者配置菜单且不影响其他租户

#### AC-R004-01 — 导航与菜单库存同步

- Given 任一适用租户的完整菜单树及平台菜单定义（若适用）。
- When 查找销售变声统计，依次隐藏/恢复、调整排序并保存；另做一次取消。
- Then 同一名称/路由/父级的配置联动本租户侧栏，隐藏后库存仍可找回；取消无改动，其他租户配置不变。

#### AC-R005-01 — 无权限与租户隔离

- Given 两租户相同销售显示名，或本租户菜单/父级隐藏、权限不允许的状态。
- When 切换租户、直接打开路由或查询。
- Then 不拼接不同租户数据，状态不串用；沿用现有可见性和权限处理，不自动开启隐藏父级、不放宽授权；菜单库存与展示权限分开。

#### AC-R006-01 — 零、空、失败分别表达

- Given 有效零次数、有条件但无匹配销售、读取失败三个 Mock 状态。
- When 查询或重试。
- Then 分别显示 0、暂无数据、加载失败与重试；加载中禁用重复查询；失败不渲染为全部 0，重试沿用已提交条件。

#### AC-R007-01 — 静态边界与视觉

- Given 当前管理页样式及标明来源的合成数据。
- When 在 Chrome 打开新页及菜单树，检查表头、数值、筛选、滚动、键盘焦点与取消。
- Then 筛选主按钮、快捷日、表格和分页继承销售使用统计同一共享样式，来源可识别，无真实后台写入；日期查询/次数排序/本地导出可操作，不宣称为真实实时次数。

### 6.1 不变量

- INV001：租户 A 的次数、人员和菜单配置不能出现在租户 B。
- INV002：刷新、查询、导出、试听不会增加统计值。
- INV003：同一独立任务最多贡献 1 次；统计次数是非负整数，失败/未知不得伪装成 0。
- INV004：数据展示新增菜单必有对应管理项；隐藏不等于从完整库存移除。
- INV005：本地演示不写真实后台；所有租户有入口不代表所有租户/账号已配置变声。

本地事件依据包括 tenantId、salesId、departmentId、taskId、首次成功时间、状态；仅用合成事件验证，不存语音内容、客户身份、真实联系方式。时间范围采用含首日零点、排除末日次日零点，界面表现为含首尾自然日。

### 8.2 权限

沿用 051 已有菜单/父级可见性及权限表现，不新建角色或跨部门授权；菜单管理只由当前已有可操作角色编辑。隐藏入口不是新的服务端安全保证，本原型不宣称实现真实鉴权。

### 8.3 隔离

统计和菜单状态使用稳定租户键，不按品牌名判断资格；相同销售显示名不合并。未配置账号没有新的变声事实，不能合成“真实使用”；明确的历史成功事实也不因当前配置变化而抹去。本轮 Mock 全为可区分来源的合成演示。

## 9. 端与租户差异

Base R001–R007 适用于所有已登记租户；仅品牌、销售、部门与已有菜单权限配置不同。六个艺星租户和九个其他租户业务口径相同。PC/APP 的发送及语音条保持原合同。本功能不授权后续自动扩展新的租户环境。
