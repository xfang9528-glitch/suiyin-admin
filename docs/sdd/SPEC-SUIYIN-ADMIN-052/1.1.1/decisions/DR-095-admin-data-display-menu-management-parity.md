# DR-095：数据展示新增菜单必须同步菜单管理

## 类型

产品 / Admin / 多租户

## 状态

已采纳。来源为房总 2026-09-20 本任务的明确指令；本记录忠实固化该要求，不代表另行批准尚未确认的变声计数口径。

## 日期

2026-09-20

## 项目

碎银管理后台 HTML 原型，所有租户；后续对应工程交付沿用同一行为要求。

## 背景

「数据展示」侧栏入口与「系统管理 → 菜单管理」中的菜单库存、显示状态和排序共同表达同一功能。如果仅增加统计页面或侧栏入口，管理员将无法在菜单管理里找到、控制该入口，菜单配置与实际导航会不一致。

房总原话：“你记个DR 凡事这里增加，对应的菜单管理也要增加哟”。本次先提出所有艺星租户新增销售变声统计，随后明确将功能范围扩大为所有租户。

## 决策

1. 今后在管理后台「数据展示」新增二级分类时，同次修改必须补齐对应的「菜单管理」项；不能只增加页面或侧栏链接。
2. 两处使用一致的稳定菜单身份、名称、路由和父级关系；显示/隐藏、排序及已有权限属性沿用当前菜单机制。存在平台菜单定义层时，同步登记该定义，避免租户菜单找不到功能源。
3. 覆盖功能的每个适用租户；所有租户通用功能应在所有当前登记租户的菜单库存中具备对应项，不能只给首个演示租户补齐。此规则不自动新增环境或恢复被排除的租户。
4. 菜单管理对显示/隐藏、排序的修改必须联动同租户侧栏；菜单项隐藏后仍保留在完整菜单库存中可恢复，不影响其他租户。保留已有父菜单与权限边界，不因新增功能而放开原有权限。
5. 验收必须同时覆盖「入口可打开正确页面」和「菜单管理可查到且配置生效」；只检查侧栏出现文字不算完成。
6. 本次「销售变声统计」按房总最新指令适用所有租户。次数定义以其 Feature SPEC 的审核结论为准；全租户统计入口不表示所有租户或账号已经完成变声配置，DR-093 继续有效。

## 后果

- **好的：** 新功能可被管理员找到和管理，减少导航存在但配置缺失、跨租户遗漏和显示状态失配。
- **代价：** 每次新增统计分类都需核对导航、菜单库存、平台定义（如适用）及租户配置，保留相应验收证据。
- **运行边界：** 本轮只涉及静态 HTML 原型与本地演示；不修改线上菜单或生产仓。原型未收到“完整推送”前不提交、推送或发布。

## 重新评估信号

菜单管理被明确废弃、导航与菜单完全由同一权威注册源自动生成，或房总批准新的菜单权限/发布机制时，重新评估实现与检查方式；在此之前，功能与管理入口同步的用户结果持续有效。
