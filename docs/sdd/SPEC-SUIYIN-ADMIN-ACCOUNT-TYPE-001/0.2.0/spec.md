# 全部账号状态按个微和企微分别展示

## 1. 审核摘要
- **用户问题**：平台管理员只能看到环境账号合计，无法区分个微、企微分别有多少账号在线或掉线。
- **完成后变化**：每个环境先展示个微、企微数量，再展示汇总；在线、掉线账号也按类型分组。
- **本次范围**：`bzds / allWeChatStatus` 的微信账号页签；每类按“总数 / 在线 / 掉线”排列，汇总置底。
- **明确不做**：不改真实业务或生产代码；本轮已明确授权原型完整推送、工程合同及创建Admin Issue。
- **需要房总拍板**：无；房总于2026-10-02回复“执行”，批准Q001设计和Q002各环境只读核对范围（含艺星）。
- **最新用户纠正**：账号创建时即确定个微或企微，不存在第三种“待核对”业务类型。旧版把采集缺口引入界面的做法撤销；仅保留两类及汇总。
- **AI 新提案**：无；本轮直接落实用户纠正，不新增业务状态或权限。

## 2. 用户问题与预期结果
US01 面向拥有平台页面访问权限的管理员，检查各环境个微、企微状态。O001：不跳出总览即可读出两类数量和账号名单；O002：所有账号按创建时确定的类型恰好归入一类，不展示采集过程状态。已核实 bzds 设计样例为：个微 **3 / 3 / 0**、企微 **5 / 0 / 5**、汇总 **8 / 3 / 5**。

## 3. 范围
### 3.1 In Scope
保留现有环境行，在统计列加入个微、企微分项并将汇总置底；两侧名单按个微、企微分组；零值、空名单；原排序、滚动、代理页签和权限回归。
### 3.2 Out of Scope
Flutter / React / Go 生产端；在线同步或业务写入；修改总览状态口径；批量调整其他管理页；本次不实施生产功能。
### 3.3 适用矩阵
仅 Admin 的 bzds 平台 `allWeChatStatus` 适用；其各环境保持原边界，不把 bzds 类型样本复制给其他环境。继承 `profiles/workspace-map.md` §5 与现有 Admin 设计规范；业务面为Admin网页；工程Issue平台标签用PC，Flutter PC客户端与APP不适用。

## 5. 用户场景与验收
### US01 — 查看各环境分类数量和账号状态
#### AC-R001-01 — 分类在前、汇总在底
- Given 已核实 bzds 总览与类型证据。
- When 打开微信账号页签。
- Then 统计列依次为个微3/3/0、企微5/0/5、汇总8/3/5，均明确总数/在线/掉线含义；在线及掉线列分别按个微、企微排列。
#### AC-R002-01 — 分类数量与名单一致
- Given 类型完整且原总览数量与名单一致的环境。
- When 逐类核对计数及名单。
- Then 每类总数等于在线加掉线；对应名单条数等于计数；两类各项相加等于汇总，原总览名单每个条目恰好出现一次。
#### AC-R003-01 — 重名保留、类型匹配不猜身份
- Given 同环境两个 `cxy2` 均有企微证据，或同名候选类型冲突/条数不符。
- When 分类该环境总览条目。
- Then 前者保留两个企微条目；后者先补齐对应来源，必要时刷新该环境完整快照并重新匹配；不按名称、位置或其他环境样本猜测，不引入第三类业务状态。
#### AC-R004-01 — 类型为必填二选一
- Given 环境缺少类型证据，或原总览与明细状态不同，或原数量与名单不一致。
- When 展示分类。
- Then 发布至本地预览的Mock每个条目必须有wx或qw；数据缺口仅作为采集/开发校验失败，不能渲染第三分类或“仅含已核实”等业务外说明。账号状态取相应总览快照，不能单独借明细状态改写。
#### AC-R005-01 — 零与空名单明确
- Given 类型已完整核实的环境某类计数为0，或整个环境总数为0。
- When 展示该行。
- Then 已确认零显示0，对应分组显示“无账号”；缺证据不显示为已确认0；全空环境仍保留两个分类和汇总。
#### AC-R006-01 — 既有体验与权限不回退
- Given 已有页面访问权限、排序和页签滚动位置，或其他租户/无权限入口。
- When 排序、滚动、切换代理页签后返回或访问其他入口。
- Then 排序三态、固定表头、页签滚动恢复、代理118卡片及原权限保持，键盘可操作，长名单可滚动，其他租户不展示 bzds 类型样本。

## 7. 状态与交互
只读分类→展示个微、企微及汇总；读取失败→保留现有错误及重试；已确认空→0/无账号。采集缺口不是业务状态。排序/页签保留 hover、focus、selected 和键盘行为；分类文本无点击暗示。溢出沿用表格滚动，状态有文字不只靠颜色。刷新重开读本地快照；无编辑、取消或保存动作；权限不足沿用原入口反馈。

## 8. 数据、权限与隐私
环境、原汇总、在线/掉线名单取 E003；类型、人设名称和启用状态取本轮各环境只读明细，批准时仅 E004 完整，后续采集分别保存本地证据。`cxy2`保留两条；空环境名保持原样；不采集密码、凭据或额外业务字段。仅现有可访问该平台页角色可见，权限不扩大；原型只读本地Mock，不发真实业务请求。完整推送只发布经过最小隐私处理的账号名/类型/状态快照及合同；名称中的完整手机号使用掩码，数量、类型、顺序和重名条目保持。原始DOM、采集截图、内部证据及凭据不进入公开仓。Q002已批准只读核对总览涉及的各环境（含艺星）账号明细中的名称、类型、状态、启用状态；不做业务写入。

原型采集中的精确名称多重集合匹配仅用于构建静态样本。正式Admin工程必须按账号稳定ID读取创建时已保存的类型字段；不使用姓名判断类型、不复制采集脚本、不把本次固定数量写死在生产逻辑中。分类使用同一账号集合和同一查询结果中的状态，保持当前平台访问权限。
