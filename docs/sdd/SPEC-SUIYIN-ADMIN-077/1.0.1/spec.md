# 艺星、画美和傲丽咨询术语与岗位角色

## 1. 审核摘要

- **用户问题**：指定医美租户的账号表、弹窗、筛选与相关页面仍称人员为销售，角色不能准确表达线上咨询、现场咨询和科室助理。
- **完成后变化**：这些租户的界面统一称咨询；账号权限角色可选择线上咨询、现场咨询、科室助理；账号入口保持已确认的“碎银账号”。
- **本次范围**：现有六个艺星租户及画美西安、傲丽西安；Admin 文案和本地角色演示，不改变线上权限。
- **明确不做**：生产实现、真实人员改岗、重新分配客户、定义三种岗位的差异权限。
- **需要房总拍板**：无；Q001已获2026-09-30房总“执行”批准。
- **AI 新提案**：已批准。原“销售”角色默认改名为“线上咨询”，另提供“现场咨询”“科室助理”可选；其他现有角色保留，不凭名称把客服、网咨、接待或管理员自动合并。三类岗位先表达本地角色选择，不额外授予权限。

## 2. 用户问题与预期结果

### 2.1 用户与场景

医美后台管理员创建、编辑碎银账号，查看咨询人员、选择权限角色，并在相关管理和统计页查询人员。

### 2.2 用户问题

同一岗位在筛选框、表头、编辑标题和字段中反复被称为销售；原单一销售角色不能表达用户指定的三类岗位。

### 2.3 完成后用户能感受到的变化

截图中的销售姓名、修改销售、销售名称、销售手机号、销售微信昵称分别显示为咨询姓名、修改咨询、咨询名称、咨询手机号、咨询微信昵称；可以明确选择指定的三类岗位。

### 2.4 成功信号

| ID | 可观察信号 | 判定方式 |
|---|---|---|
| O001 | 八租户的系统人员术语一致 | 导航、页签、表格、筛选、弹窗和提示检查 |
| O002 | 三岗位可选且回填一致 | 新增/编辑、取消、保存、刷新 |
| O003 | 其他租户和非销售角色保持 | 对照租户及多角色账号回归 |

## 3. 范围

### 3.1 In Scope

- 明确目标八租户；界面系统文案中的销售人员称谓统一改为咨询，包括销售统计、销售使用统计、销售接待等页面名称，以及咨询姓名、专属咨询、全部咨询、咨询发送等相关字段和提示。
- 保持“碎银账号”入口，不因批量替换恢复旧名称。
- 账号表中的角色值、创建/编辑角色选项、当前租户角色目录同步三种岗位名称；继承当前多选能力。
- 旧本地数据兼容、字段匹配、搜索、取消、保存失败和跨租户隔离。

### 3.2 Out of Scope

- Flutter / React / Go 生产端、真实后台与真实角色权限配置。
- PC/APP 原型、非目标租户、统计计算或查询逻辑变更。
- 修改人员姓名、微信昵称、自由文本、聊天正文、历史业务记录原文等用户数据中的“销售”字样；改的是系统称谓和明确角色值。
- 自行解释客服、网咨、网咨接待、接待、渠道主管等既有角色与三类岗位的对应关系。
- 为画美、傲丽复制其他租户账号、部门、角色权限或业务样本。
- 本规格不创建工程Issue。日常阶段不自行触发发布；后续用户已授权完整推送，当前文档、单文件和远端SDD随076交付。

## 5. 用户场景与验收

### US01 — 管理员按医美岗位维护账号

- **用户**：目标租户管理员。
- **前置条件**：进入对应tenant的本地Admin原型。
- **目标**：用咨询术语查询和编辑账号并选择正确岗位。
- **独立价值**：字段与岗位可理解，显示和回填一致。

#### AC-R001-01 — 指定租户与其他租户
- Given 八个目标租户及其他九租户。
- When 打开同类界面。
- Then 目标租户的系统称谓为咨询，其他租户保留销售；账号入口均保持碎银账号。

#### AC-R002-01 — 全部可达展示与字段对应
- Given 账号列表、筛选、创建/编辑弹窗及已有相关统计/聊天/菜单页面。
- When 查询、编辑、取消、重新进入或导出当前原型支持的结果。
- Then 对应界面称谓一致，无旧销售提示回弹；字段值仍对应同一身份，查询结果、统计口径和业务值不变。

#### AC-R003-01 — 三岗位与现有角色
- Given 原角色为销售或其他角色的账号及角色目录。
- When 打开角色选择并选择线上咨询、现场咨询或科室助理。
- Then 三岗位可选、选中和回填一致；按Q001承接原销售；其他原角色与账号多选关系保持，不添加额外权限。

#### AC-R004-01 — 保存、取消与恢复
- Given 有本地修改或旧销售缓存。
- When 取消、保存、刷新、重复保存或本地写入失败。
- Then 取消不写；保存后同租户回显；旧数据按Q001解释且打开不做隐式写入；失败保留草稿和旧已存值并提示；重复操作不重复增加角色。

#### AC-R005-01 — 待采与隐私边界
- Given 新租户资料待采、未知角色或含销售字样的自由文本。
- When 加载页面或调整角色。
- Then 不填入其他租户数据，不猜未知角色归属，不修改自由文本，不请求真实业务写API；已有待采提示保留。
