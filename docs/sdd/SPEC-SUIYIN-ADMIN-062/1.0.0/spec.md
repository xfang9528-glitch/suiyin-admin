# 预约记录列表与预约量组合图

## 1. 审核摘要

- **用户问题**：管理者查看预约记录时，需要逐行阅读、翻页，难以快速判断所选范围的预约总量和日期分布。
- **完成后变化**：保留逐条查看的列表，同时可切换图表，一眼看出有多少预约、哪天较多、期间累计多少。
- **本次范围**：预约记录页增加「列表 / 图表」切换、一个总量数值、一张柱形与折线组合图，共用现有筛选。静态 HTML 与本地演示数据。
- **明确不做**：到院、成交、营收、转化率、成功率、同比环比、预约创建/取消、生产接口；工程实现另走正式 Issue 流程。
- **需要房总拍板**：无；2026-09-21 房总回复“按这个来”，批准 Q001/Q002 推荐方案。
- **AI 新提案**：柱形为每日预约量，折线为所选期间累计预约量，按预约时间归日；默认保留列表，点击图表查看概览；先复用已有预约入口，不添加跨租户总览。上述方案已由房总于2026-09-21批准。

已批准信息结构（已实现；本地验收见 verification.md）：

```text
预约记录
原有筛选：客户 / 预约日期 / 项目 / 科室 / 医生 / 院区 /
          创建人 / 创建时间 / 创建人部门          查询 重置

列表 | 图表

预约总量 N 条             按预约日期统计 · 已应用范围
每日预约量（柱形，左轴）  期间累计预约量（折线，右轴）
                    日期从早到晚
```

## 2. 用户问题与预期结果

### 2.1 用户与场景

- 用户：有权查看当前租户预约记录的管理人员。
- 场景：查询一段时间或某项目、医生、院区、创建人、部门的预约情况。
- 当前做法：筛选后逐行阅读列表，无法从首屏判断完整结果的每日变化。

### 2.2 用户问题

列表适合核对某条预约，但翻页和手工统计增加了判断总量及高峰日期的成本；预约时间和创建时间混用还可能让人误解结果。

### 2.3 完成后用户能感受到的变化

在同一页切换展示方式即可看总量和走势，需要核对时切回同一批预约明细。

### 2.4 成功信号

| ID | 可观察信号 | 判定方式 |
|---|---|---|
| O001 | 无须翻完列表即可读出所选范围预约数与日期分布 | 原型人工观察 |
| O002 | 柱形合计、累计末点、汇总数与完整筛选记录数一致 | 固定演示数据核对 |

### 4.1 已发现冲突

1. 055 R004 和现行设计规范禁止向所有统计页随意添加汇总卡。本次 E001 明确提出预约总量和图表，本规格批准后仅给预约记录页新增总量/组合图，不推广到其他页面。完整推送时须同步预约专属规则并记录来源收敛，旧快照保留历史。
2. 现有源文件的20条样本与历史293条分页总数不是同一个完整数据集，不能绘制“293条完整趋势”，也不能把20条标成真实全部预约。R007 强制区分样本和完整演示。
3. 本轮用户截图是新证据，现有 JSON 为2026-09-18快照；不能混合两者拼接声称同一时点的全量结果。

## 5. 用户场景与验收

### US01 — 同一页查看预约总量与走势

#### AC-R001-01 — 视图切换
- Given 当前租户预约记录已有一批应用后的查询结果。
- When 从默认列表切到图表，再切回列表。
- Then 原有筛选不变，图表出现总量和组合图，列表保留原列及查看动作；已应用结果不重置，列表分页位置保留。

#### AC-R002-01 — 预约时间归日
- Given 同一演示客户有两个不同预约记录 A/B，均9月21日创建，预约时间分别为9月25日和9月26日。
- When 查询覆盖两个预约日的日期范围。
- Then 总量为2；25日、26日各1；不计入21日，也不按客户去重。相同稳定预约键重复加载不增量。

#### AC-R003-01 — 柱线一致
- Given 完整演示结果在9月21日至23日分别为2、0、3条。
- When 查看图表并悬停或键盘聚焦日期。
- Then 柱形值为2/0/3，折线为2/2/5，总量为5；提示包含日期、当天预约量、期间累计预约量。双轴分别标明含义与单位“条”，均从0起。

#### AC-R004-01 — 筛选、分页和口径一致
- Given 同时设置预约日期、创建时间和项目，列表分两页。
- When 点击查询、翻页或切换视图。
- Then 两种日期筛选取交集，聚合仍按预约时间；图表与总量按所有匹配记录计算，不随列表翻页变化。仅修改输入未查询时，图表仍显示旧的已应用条件并标注待查询。

### US02 — 正确理解边界和数据来源

#### AC-R005-01 — 日期范围与单日
- Given 设置上海自然日范围9月21日至23日。
- When 查询。
- Then 包含21日00:00至24日00:00前的预约，完整数据中间零值日补0；单日显示单柱及累计单点；无日期范围时只取结果中有效预约日期的最早至最晚，不暗加最近30天。

#### AC-R006-01 — 空态、失败、缺日期
- Given 完整演示无匹配记录，或数据加载失败，或一条记录缺少有效预约时间。
- When 查看结果。
- Then 已确认无匹配显示0及“当前筛选暂无预约记录”；加载失败显示重试而非0；无预约日期的记录在无预约日期筛选时计入总量并另标“预约日期缺失 N 条”，不落入日期桶，柱形合计+缺日期数=总量；启用预约日期条件后该类记录不匹配且不能静默补日期。

#### AC-R006-02 — 无效条件与长时间段
- Given 日期起止倒置、仅填写一侧，或图表范围有较多日期。
- When 尝试查询或横向查看。
- Then 无效条件在对应字段提示修正且保留上次结果；较多日期使用图表区域横向滚动及适度稀疏轴标签，每个日期的数据和提示仍可访问，不挤压筛选或截掉日期。

#### AC-R007-01 — 样本不冒充总量
- Given 仅有20条采样明细但分页文本写293条。
- When 切换图表。
- Then 显示“样本预约量”“仅依据已采样记录，非全部预约”，无法确认的日期不补真实0；不从293分摊曲线。完整合成数据仅在独立、明确标识的演示数据集中验证总量与零值，列表同步使用同一数据集。

#### AC-R008-01 — 租户与权限
- Given 当前在深圳查看某医生结果，然后切换广州，或当前角色没有预约记录访问权限。
- When 进入预约记录。
- Then 不保留深圳实体筛选、结果和浮层；参考样本明确标出来源且不作为广州统计，无本租户可统计数据则显示来源说明；无权限时不显示图表和总数，不新增跨租户访问入口。

### 6.1 不变量

- INV001：完整数据且日期有效时，总量=全部匹配预约条数=柱形合计=累计末点；无日期记录按R006另列，全部无有效日期时不画伪0曲线。
- INV002：列表翻页、重复切换视图不会改变预约总量。
- INV003：预约量不表示到院量、成交量或同步成功量。
- INV004：采样未知不等于0；当前租户、参考来源与演示身份不能混淆。

### 7.3 进入、退出与恢复

- 入口：医生管理→预约记录→图表。
- 返回：切换列表；查看详情仍使用原有只读流程。
- 取消：日历 Escape/外点沿用既有行为；提示 Escape/失焦关闭。
- 重复操作：反复切换或查询同条件不改变结果、不重复累加。
- 刷新/重开：恢复源页默认空筛选和列表，数据身份仍显式显示；本轮不新增持久化偏好。
- 失败恢复：重试当前已提交条件；不可将上次结果伪装成新条件结果。
- 触控：可点击日期柱/点查看同一提示；没有提交、删除或破坏性确认动作。
