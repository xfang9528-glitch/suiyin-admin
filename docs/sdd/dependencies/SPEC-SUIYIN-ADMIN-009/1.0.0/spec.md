# AI 辅助消息使用统计

## 1. 审核摘要

> 房总先看本节即可判断方向；正文用于追溯和实现。

- **用户问题**：管理者目前只能看到销售发了多少消息，无法分清哪些由 AI 直接发送、哪些参考 AI 后编辑发送、哪些完全手动录入；因此既看不清 AI 实际使用量，也缺少后续评估 AI 是否帮助客户等级提升和到店转化的可信基线。
- **完成后变化**：管理者可在管理页按日期、销售账号或部门查看「AI 直发 / AI 参考 / 手动录入」消息数、AI 辅助合计与占比；所有租户都能打开同一页面，没有本租户数据时正常显示空态；首版不追溯历史消息，也不宣称 AI 已经带来等级或到店率提升。
- **本次范围**：在「数据展示」新增「AI 辅助统计」，复用话术统计的时间、维度、部门、账号搜索与分页方式；仅聚合本功能上线后产生的三类消息，所有租户共用页面与口径。
- **明确不做**：本次不做 D→A 等级提升率、到店率提升或因果归因，不查看消息正文，不接真实接口，不进入 Flutter / React / Go 生产端实现。
- **需要房总拍板**：无；Q001–Q004 已全部关闭。
- **AI 新提案**：已批准——R002 首期只统计销售发出的单聊文本消息；R006 增加 AI 辅助合计 / 占比；R009 将效果归因留到独立后续规格。

## 2. 用户问题与预期结果

### 2.1 用户与场景

- 用户角色：拥有管理页「数据展示」权限的管理者、销售负责人。
- 触发场景：管理者需要按天、周、月或自定义区间复盘团队是否使用 AI 辅助回复，并比较销售账号或部门的采用情况。
- 当前做法：只能从销售使用统计、话术统计或零散反馈判断消息使用情况，无法按 AI 来源标签聚合三类使用量。

### 2.2 用户问题

管理者不知道 AI 是被直接采用、作为参考后采用，还是完全没有被使用。没有统一的上线后使用基线，未来即使观察到客户等级或到店率变化，也难以判断数据是否可比较。

### 2.3 完成后用户能感受到的变化

管理者打开一张与话术统计操作习惯一致的表，就能按时间、账号和部门比较三类消息量，看到 AI 辅助合计与占比。统计从功能上线后开始累计；切到没有数据的租户或时间范围时，页面仍完整呈现并显示普通空态。

### 2.4 成功信号

## 3. 范围

### 3.1 In Scope

- 「数据展示」菜单新增「AI 辅助统计」入口，位置紧邻「话术统计」。
- 快捷日期：今天、昨天、本周、本月；支持自定义开始日与结束日。
- 维度：按销售账号 / 按部门。
- 筛选：部门；按销售账号维度时支持「销售账号 / 姓名」关键词。
- 账号表：销售账号、所属部门、AI 直发、AI 参考、手动录入、AI 辅助合计 / 占比。
- 部门表：部门、账号数及上述聚合指标。
- 口径说明明确「只从本功能上线后开始累计，历史消息不追溯」。
- 加载、筛选无结果、上线前区间无数据、统计失败、无权限和横向溢出状态。
- 全部租户共用同一页面；当前原型只为成都艺星准备有数据 mock，其他租户展示普通空态。

### 3.2 Out of Scope

- D→A、任意等级迁移率、到店率提升、成交率提升及 AI 因果归因。
- 按好友、消息正文、AI 建议原文或销售修改内容下钻。
- 为来源标签补打或追溯任何功能上线前的历史数据。
- 未标记数、标签覆盖率或其他数据质量监控指标。
- 导出、趋势图、排行榜奖惩、自动提醒和目标阈值。
- 真实认证、API、数据库、共享持久化或线上入口。
- PRD、流程图、设计规范、`_inline.html` 同步及 commit / push / tag；除非房总之后明确说「完整推送」。
- Flutter / React / Go 等生产端实现不在本规格范围。

## 5. 用户场景与验收

### US01 — 按同一套筛选习惯查看 AI 使用量

- **用户**：拥有「数据展示」权限的管理者。
- **前置条件**：当前租户存在来源标签聚合 mock。
- **目标**：按时间、销售账号或部门查看 AI 采用情况。
- **独立价值**：不依赖后续效果分析，也能先建立团队 AI 使用基线。

#### AC-R001-01 — 时间筛选与日期边界

- Given 页面首次打开或管理者选择任一合法日期区间。
- When 选择今天、昨天、本周、本月或自定义起止日并执行搜索。
- Then 首次默认本月，快捷项写回日期输入；起止日均按 Asia/Shanghai 自然日包含，开始日晚于结束日时不刷新表格并提示「开始日期不能晚于结束日期」。

#### AC-R002-01 — 三类来源只按标签计数

- Given 功能上线后的同一筛选范围内存在 AI 直发、AI 参考和手动录入三类销售消息。
- When 页面聚合消息来源。
- Then 只按消息现有来源标签互斥落入 AI 直发 / AI 参考 / 手动录入三类，不根据消息内容二次推断来源。

#### AC-R003-01 — 只从功能上线后开始累计

- Given 功能统计起始时刻为 T，查询范围同时包含 T 前和 T 后的消息。
- When 页面计算三类消息数。
- Then 只统计 `sent_at >= T` 的消息，T 前历史消息完全不追溯；查询范围整体早于 T 时页面显示普通空态。

#### AC-R004-01 — 账号与部门聚合一致

- Given 同一部门下有多个销售账号。
- When 从「按销售账号」切到「按部门」。
- Then 部门的三类计数分别等于账号计数之和，AI 辅助率用部门汇总后的分子 / 分母重新计算，不取账号百分比平均值。

#### AC-R005-01 — 筛选切换和重置可预期

- Given 管理者已选择日期、部门和账号关键词并翻到非第一页。
- When 改变维度、执行搜索或点击重置。
- Then 日期和部门在维度切换时保留、账号关键词仅在账号维度显示，任何新查询回到第 1 页；重置恢复本月 / 按销售账号 / 全部部门 / 空关键词。

#### AC-R006-01 — 指标表和默认排序

- Given 当前筛选结果包含多个销售账号或部门。
- When 结果表渲染。
- Then 表格展示本规格定义的列，默认按「AI 辅助合计 = AI 直发 + AI 参考」降序；AI 辅助率以已标记三类消息为分母，分页为 10 / 20 / 50 条且默认 20 条。

### US02 — 在数据不足时避免得出错误结论

- **用户**：切换企业或查看早于标签上线日期区间的管理者。
- **前置条件**：当前租户没有上线后数据、查询范围早于统计起始时刻、筛选无结果、无权限或统计失败。
- **目标**：分清「没有使用」「没有标签」「没有结果」和「加载失败」。
- **独立价值**：避免把数据缺失当成销售行为或 AI 效果。

#### AC-R007-01 — 所有租户呈现完整页面

- Given 当前企业是艺星深圳或任一没有本租户统计数据的企业。
- When 打开「AI 辅助统计」。
- Then 筛选栏、表头和分页结构正常呈现，结果区显示「当前筛选范围内暂无数据」；页面不显示「未接入」提示，也不借用成都艺星 mock。

#### AC-R008-01 — 空、错、无权限状态分开

- Given 分别出现合法筛选无结果、统计加载失败和当前账号无数据展示权限。
- When 页面反馈状态。
- Then 分别显示「当前筛选范围内暂无数据」、带「重试」动作的失败说明、以及无权限说明；错误与无权限不能伪装成普通空态。

#### AC-R009-01 — 首版不展示未经定义的效果归因

- Given 当前只有消息来源标签、AI 客户等级和成都 PDM 到店状态等各自数据语义。
- When 管理者查看本页。
- Then 页面只陈述 AI 使用量，不出现「AI 帮助 D→A」「AI 提升到店率」的数值或因果文案；效果分析须在 Q004 关闭后另建规格。

#### AC-R010-01 — 统计不泄漏消息正文或其他租户数据

- Given 管理者查看账号或部门聚合结果。
- When 页面加载、筛选、切换维度或展示口径说明。
- Then 只展示当前租户的聚合计数和现有账号 / 部门标识，不展示消息正文、AI 建议内容、客户身份或其他租户记录，并继承话术统计的可见权限范围。

### 6.1 不变量

- INV001：同一条已标记合格消息只能属于 AI 直发、AI 参考、手动录入之一。
- INV002：功能上线前的历史消息永远不进入本页任何计数。
- INV003：任何聚合结果只含当前租户数据；没有本租户数据时显示空态，不从其他租户借数。
- INV004：AI 辅助率只描述使用构成，不等于 AI 对等级、到店或成交的提升。
- INV005：部门比率由部门汇总计数计算，不能平均账号比率。

### 7.4 文案合同

| 场景 | 文案 | 为什么这样写 | 禁止写法 |
|---|---|---|---|

| 效果说明 | 本页仅统计 AI 使用量，不代表 AI 已带来等级或到店提升 | 防止把相关性写成因果 | AI 助力客户升 A、AI 提升到店率 |
