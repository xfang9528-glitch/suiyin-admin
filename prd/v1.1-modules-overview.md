#### 话术统计 · 关键定义
- **统计对象**：单聊场景下的话术发送记录（不含群聊、不含非话术消息）
- **话术使用量**：同一<销售账号或部门>给同一好友发的同一条话术，无论次数都只计 **1 次**
- **沟通好友数**：窗口内该<销售账号或部门>发过**任何消息**的好友数（不限话术）
- **使用率** = 话术使用量 ÷ 沟通好友数（语义："每个被沟通的好友平均收到几条不同话术"）
- **维度切换**：「按销售账号」与「按部门」一键切换，部门聚合 = 该部门下所有销售账号的求和
- **下钻明细 modal**（2026-05-08 重构）：
  - **表头 5 列**：# / 话术 / 使用条数·同好友去重 / 沟通好友数 / 使用率
  - **话术列展示规则**：与话术库层级关联，仅展示「二级：三级：四级」类目路径，**不展示一级**（一级=公共/私有/收藏/常用）、**不展示具体内容**（五级=单条消息）。无四级时只展示二三级，依此类推
  - **聚合粒度**：按 `(二级, 三级, 四级)` 类目聚合，账号视角和部门视角都走相同聚合（部门视角是该部门下所有账号明细汇总后再聚合）
  - **沟通好友数衰减系数（mock）**：按二级类目业务情境差异化——一次性破冰类（品牌/医院介绍 0.92、竞对分析 0.88）保留率高；多产品轮发类（皮肤产品介绍 0.65、明星美学 0.65）；系列轮发类（全院医生 0.55、明星博主do脸分享 0.55）保留率低
  - **排序**：按「使用条数」由多到少
  - **分页**：modal 底部分页器（10/20/50 条/页，默认 10），仅页码翻页无跳页输入
- **时间维度**：单日 / 多日（今天/昨天/本周/本月 + 自定义起止）
- **mock 数据源**：参照 `yestar-pc-chat/prototype_v1.0.html` 的真实话术库 `scriptData`（14 个大类，~70 条 l4 条目，覆盖品牌/医院介绍、全院医生/医生技术介绍、皮肤产品介绍、术后注意事项、微创产品介绍、整形外科-鼻部/眼部、明星博主do脸分享 等）；销售账号 mock 改用 `mock-data.js / SALES_ACCOUNTS`（194 条艺星线上真号）
- **销售账号列展示**（2026-05-12 房总定）：单行只显示账号名，**不再展示**灰色微信端昵称（alias）
- **需求来源**：陈薇 2026-05-02（艺星抖音IP团队），统计各部门工具包（话术库）使用率，工程师：梁晨

#### AI 辅助统计 · 关键定义（2026-08-05 房总批准）
- **Source Contract**：`SPEC-SUIYIN-ADMIN-009@1.0.0`；本节是产品交付摘要，冲突时以该版本 SPEC 为准。
- **统计对象**：当前租户、当前日期范围内，由销售发出的单聊文本消息；只按已有来源标签互斥落入 `AI 直发 / AI 参考 / 手动录入`，不根据正文二次推断。
- **历史边界**：只从本功能在当前环境的实际上线时刻开始累计，不估算、不补打、不追溯上线前消息；不展示未标记数或标签覆盖率。
- **筛选**：今天 / 昨天 / 本周 / 本月、自定义起止日、账号 / 部门维度、部门筛选；账号维度另支持销售账号 / 姓名关键词。默认本月、按销售账号、全部部门、20 条/页。
- **指标**：`AI 辅助合计 = AI 直发 + AI 参考`；`AI 辅助率 = AI 辅助合计 ÷（AI 直发 + AI 参考 + 手动录入）`，分母为 0 显示「—」；默认按 AI 辅助合计降序。
- **部门聚合**：三类数量分别对部门成员账号求和；占比由部门汇总后的分子 / 分母重算，不平均账号百分比。
- **租户范围**：所有租户都显示完整页面；成都艺星首期已有标签数据，其他租户没有本租户数据时显示「当前筛选范围内暂无数据」，不得借用成都数据，也不显示「未接入」。
- **状态**：加载、普通空态、加载失败 + 重试、无权限、非法日期和横向溢出分别反馈，错误与无权限不能伪装成空态。
- **效果边界**：本页只建立 AI 使用量基线，不展示 D→A、到店率、成交率提升或因果结论；后续效果分析另建 SPEC。
- **详细 PRD**：`prd/ai-assisted-message-stats.md`。

#### 群邀请提及率 · 关键定义
- **统计对象**：销售给"新加好友"使用过的"群邀请话术"——按话术分类聚合，多变体均算命中
- **3 个目标群**：微整填充群（千元福利大礼包路径）/ 眼部群（案例驱动路径）/ 范院群（范院长粉丝高净值路径）
- **新增好友数（分母）**：窗口内该<销售账号或部门>**新通过**的好友总数，**不剔除**未沟通好友
- **提及量（分子）**：对每个新加好友，是否使用过对应群的邀请话术；同好友同群只计 **1 次**
- **提及率（任一）** = 已邀任一选中群的好友数 ÷ 新增好友数（多群 OR 命中）
- **单群提及率** = 邀请进该群的好友数 ÷ 新增好友数（独立计算，可叠加）
- **群多选**：3 个 chip 默认全选，可任意取消（至少保留 1 个）；取消的群对应"单群提及率"列同步消失
- **维度切换**：「按销售账号」与「按部门」一键切换，部门聚合 = 该部门下所有销售账号的求和
- **默认排序**：按"提及率（任一）"**升序**——最差靠前，便于管理者从催办最紧迫的销售看起
- **未邀好友数**：高亮可点击，直接跳到明细 modal 的"未邀"tab
- **下钻明细 modal · 双 tab**：
  - 未邀好友：按加好友时间倒序（最新最紧急），列：好友 / 加好友时间 / 最近沟通
  - 已邀好友：列：好友 / 加好友时间 / 已邀群（彩色 chip） / 邀请时使用话术原文 / 邀请时间
  - modal 内分页器：20/50/100 条/页，切 tab 各自记忆页码
- **时间维度**：单日 / 多日（今天/昨天/本周/本月 + 自定义起止）；选周以上脏数据被自然稀释
- **销售账号列展示**（2026-05-12 房总定）：单行只显示账号名（即"销售账号"字段），**不再展示**之前的灰色微信端昵称（alias），保持与其他统计页一致
- **mock 数据源**：194 条艺星线上真实账号 + 真实部门归属（2026-05-12 拉取自 `yestar.wecarepet.com/admin/wechatStatus`），统一存于 `mock-data.js` 的 `SALES_ACCOUNTS`。部门分布：自媒体 100 / 抖音IP 32 / 小红书 20 / 电商 21 / 代运营 21。stats_script / stats_invite / sales 等页面共享
- **表格分页**：与话术统计一致，10/20/50 条/页（默认 20）
- **后端协同**：话术分类标签由后端实现，前端不需改话术库 UI
- **需求来源**：房总 2026-05-07，找出"新加好友未邀群"的销售并催办

## 3. 通用约定

### 3.1 真实数据脱敏边界
- 用真实：销售/院长姓名、群名、产品名、医美科室、渠道、案例标题
- 全脱敏：手机号 `138****1234`、身份证、银行卡 — 严禁明文进 git
- 不抄图：客户头像 / 真实截图 — 用渐变占位代替

### 3.2 通用列表页范式
- 顶部筛选栏 56px：输入 + 下拉 + 日期范围 + 查询/重置 + 右侧操作按钮
- 表格区：粘性表头 + 横向滚动（min-width 触发）+ 行 hover 高亮
- 底部分页器固定 48px：总数 + 页大小 + 页码

### 3.3 弹窗范式（_edit_modal.js）
- 配置驱动，字段类型：text/number/select/textarea/switch/radio/tags/image/rich
- 默认 560px 宽，复杂场景 720-1080px
- 头部标题 + 关闭 ✕，body 表单，footer 取消 + 确认（确认绿色）
- 必填字段前 `*` 红色

#### 只读明细弹窗例外（房总 2026-05-07 拍）
- 表格类只读明细 modal **不带 footer**，关闭走右上 × 或点遮罩两种方式
- 理由：footer 单独一个"关闭"按钮属于冗余，去掉让弹窗更紧凑
- 适用：话术统计明细、群邀请提及率明细等纯展示弹窗
- 不适用：表单提交类（保留 取消+确认 footer）

### 3.4 顶栏企业切换器（2026-06-18 新增；2026-07-17 同步 PC）
- 位置：顶栏右上角「房昕」用户下拉菜单内（房昕/超级管理员 → 切换企业列表 → 退出登录）
- 触发条件：**仅多租户权限**用户显示（`ENTERPRISES.length > 1`）；单租户隐藏整个切换区
- 企业列表与 PC 原型 `ENV_ORDER` **保持同顺序、同文案**（2026-07-17 当前 16 项：佰智德三 / 诚如风险管理事务所 / 达根斯 / 厚全鸡蛋 / 锦帛服饰 / 萌爪医生 / 南苑茶庐 / 瑞熙小刘 / 瑞熙小温 / 瑞熙小周 / 天馨健身 / uid / 彦库实业 / 艺星 / 艺星深圳 / 柚子烘焙）；当前企业绿底高亮 + 「当前」标签，点其他即切换（更新顶栏品牌名；现阶段各企业内容沿用现状，后续按租户逐个迭代）
- **租户传递（2026-06-18）**：切换企业时 `_shell` 把当前租户经 `?tenant=<id>` 写进所有已打开页面的 iframe 并重载，页面据此做多租户门控（首例：好友列表 CRM 筛选仅 yestar 显示）。`SHELL_TENANT` + `withTenant(page)`；2026-07-17 账号状态页默认 `yestar-sz`
- 注：架构上管理页仍为每租户独立部署独立域名，切换器只对有跨企业权限的管理员开放

### 3.5 视觉风格（公众号克制版）
- Header：白底 + 灰边 + 绿色 ◉ logo + 浅绿"管理后台"小标签
- 通知图标：右上 🔔 + 红色数字徽章
- 主按钮：实心微信绿（仅创建/添加/确认等关键动作）
- 次按钮：白底浅灰边 + 灰字（默认），hover 变绿
- 链接按钮：公众号蓝 #576b95，不再用 #3370ff
- 状态徽章：浅色背景 + 中和色文字（柔和饱和度，参考公众号配色）
