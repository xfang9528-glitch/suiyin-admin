# 群发记录：删除数与统计入口 PRD

**版本**：v1.0  
**日期**：2026-08-05  
**关联 Issue**：[PetWebOrg/suiyin-admin#196](https://github.com/PetWebOrg/suiyin-admin/issues/196)  
**关联 PC Issue**：[PetWebOrg/flutter-suiyin#5736](https://github.com/PetWebOrg/flutter-suiyin/issues/5736)

## 1. 背景

运营管理人员复盘多条群发记录时，需要逐条打开失败详情，才能找到因好友删除销售导致的失败人数。列表中的「统计」又单独占一列，与编辑、暂停、删除、记录等行级操作分散，增加了横向阅读和操作成本。

## 2. 用户结果

运营管理人员可以直接横向比较每条任务的好友删除量，并在同一行的「操作」区域进入统计查看，不再逐条展开失败详情查数。

## 3. 列表规格

表头顺序：

1. 标题
2. 来源
3. 群发内容
4. 设定发布时间
5. 实际发布时间
6. 排除已聊天用户
7. 状态
8. 进度
9. 删除数
10. 操作

### 3.1 删除数

- 位于「进度」之后、「操作」之前。
- 数据口径：列表接口 `fail_reasons` 中 `label == "好友被删除"` 的 `count` 合计。
- 没有该分桶、`fail_reasons` 为空或历史任务没有该字段时，显示 `0`。
- 其他失败原因不计入删除数；「失败数」及其失败原因下钻口径保持不变。
- 非零值用失败色强调，`0` 使用次要文字色。

### 3.2 统计查看

- 删除独立「统计」表头和单元格。
- 原「查看」入口移动到「操作」列，文案仍为「查看」。
- 所有任务状态均保留「查看」，点击行为与原统计入口一致。
- 编辑、暂停、继续、取消、删除、记录、导出等既有状态和权限规则不变。

## 4. 多端范围

- 管理后台 Web 列表。
- 管理后台多端列表。
- Flutter PC 群发记录表格。
- 所有租户统一生效，不增加租户专属开关。

## 5. 非目标

- 不新增「总群发数量」独立列；总数继续显示在进度分母中。
- 不修改后端失败原因、数据库或统计接口。
- 不调整群发创建、编辑和任务状态操作。

## 6. 验收

- 有「好友被删除：7」时，删除数显示 `7`。
- 同时存在其他失败原因时，只统计「好友被删除」。
- 无匹配分桶时显示 `0`，页面不报错。
- 列表无独立「统计」列，操作列存在「查看」。
- 各状态原有操作仍可见且行为不变，横向滚动可到达完整操作列。
