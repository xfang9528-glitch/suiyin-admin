# 群发记录：删除数与导出入口 PRD

**版本**：v1.0  
**日期**：2026-08-05  
**关联 Issue**：[PetWebOrg/suiyin-admin#196](https://github.com/PetWebOrg/suiyin-admin/issues/196)  
**关联 PC Issue**：[PetWebOrg/flutter-suiyin#5736](https://github.com/PetWebOrg/flutter-suiyin/issues/5736)

## 1. 背景

运营管理人员复盘多条群发记录时，需要逐条打开失败详情，才能找到因好友删除销售导致的失败人数。列表中的「统计」又单独占一列，与编辑、暂停、删除、记录等行级操作分散，增加了横向阅读和操作成本。

## 2. 用户结果

运营管理人员可以直接横向比较每条任务的好友删除量，并在同一行「操作」区域的最后一个位置导出统计报表，不再逐条展开失败详情查数。

## 3. 列表规格

表头顺序：

1. 标题
2. 来源
3. 群发内容
4. 设定发布时间
5. 实际发布时间
6. 排除已聊天用户
7. 状态
8. 进度
9. 删除数
10. 操作

### 3.1 删除数

- 位于「进度」之后、「操作」之前。
- 数据口径：列表接口 `fail_reasons` 中以下两类删除原因的 `count` 合计：`label == "好友被删除"`、`label == "好友已被删除，需要对方验证"`。
- 任一删除原因出现多个同名分桶时全部求和；没有这两类分桶、`fail_reasons` 为空或历史任务没有该字段时，显示 `0`。
- 「对方拒收消息」「参数错误」「对方无法接收消息」等其他失败原因不计入删除数；「失败数」及其失败原因下钻口径保持不变。
- 非零值用失败色强调，`0` 使用次要文字色。

### 3.2 统计导出

- 删除独立「统计」表头和单元格。
- 统一移除「查看」文案；统计入口在「操作」列统一显示为「导出」。
- 「导出」始终排在该行所有操作的最后一个位置。
- 所有任务状态均保留一个「导出」，点击行为复用原统计报表能力；若原操作列已有同功能入口，则去重为一个。
- 编辑、暂停、继续、取消、删除、记录等其他既有状态和权限规则不变。

## 4. 多端范围

- 管理后台 Web 列表。
- 管理后台多端列表。
- Flutter PC 群发记录表格。
- 所有租户统一生效，不增加租户专属开关。

## 5. 非目标

- 不新增「总群发数量」独立列；总数继续显示在进度分母中。
- 不修改后端失败原因、数据库或统计接口。
- 不调整群发创建、编辑和任务状态操作。

## 6. 验收

- 有「好友被删除：238」和「好友已被删除，需要对方验证：50」时，删除数显示 `288`。
- 同时存在其他失败原因时，只统计上述两类删除原因；同类重复分桶全部求和。
- 无匹配分桶时显示 `0`，页面不报错。
- 列表无独立「统计」列和「查看」入口；「导出」位于操作列最后一个位置。
- 各状态原有操作仍可见且行为不变，横向滚动可到达完整操作列。
