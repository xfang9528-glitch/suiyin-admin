# 全部账号状态

更新：2026-10-02。唯一行为合同为 [SPEC-SUIYIN-ADMIN-ACCOUNT-TYPE-001@0.2.0](../docs/sdd/SPEC-SUIYIN-ADMIN-ACCOUNT-TYPE-001/0.2.0/spec.md)，继承056@1.0.0的静态、来源与隔离边界。本文随完整推送同步合同，不新增规则。工程切片见[交接合同](../docs/sdd/SPEC-SUIYIN-ADMIN-ACCOUNT-TYPE-001/0.2.0/issue-handoff.md)，工程平台标签为PC，具体产品界面为Admin管理页。

## 用户结果与范围

平台管理员在“平台管理 → 全部账号状态”即可分别看到每个环境个微、企微有多少在线或掉线，并对应到具体账号；汇总保留在分类之后，便于核对总量。当前入口为 `bzds / allWeChatStatus`，默认“微信账号”页签。该平台总览中的43个环境行，不等于导航中新增43个后台租户；其他租户入口与既有权限保持。

账号类型在创建时已确定，只能是个微或企微。0.1.0将证据缺口画成“待核对”分类的提案已经撤销；页面不出现第三类、已核实比例或采集过程说明。资料缺口属于开发校验失败，不被解释成个微或已确认零。

## 微信账号页签

| 区域 | 当前行为 |
|---|---|
| 环境名称 | 保留原行与原始顺序、空名称及相同名称；可按原交互排序 |
| 账号统计 | 行顺序为个微、企微、汇总；每行横向列出总数、在线、掉线，数值对齐 |
| 在线账号 | 个微组在前、企微组在后，组标题带条目数；在线账号使用原蓝色标签 |
| 掉线账号 | 个微组在前、企微组在后，组标题带条目数；掉线账号使用原红色标签 |
| 已确认空组 | 数值0，名单显示“无账号”；全空环境仍保留两类和汇总 |

每类总数等于在线加掉线，类别名单条数与计数相等，两类逐项相加等于汇总。每个原始账号条目恰好出现一次，重名不去重；同名不同类型时按各自账号身份分别展示，不能按名字认定为同一账号。bzds设计样例为个微3/3/0、企微5/0/5、汇总8/3/5，两个`cxy2`均保留在企微掉线组。样例计数不固定生产实际值。

## 来源、状态与失败

正式Admin按同环境稳定账号ID读取创建时已保存的类型，不按名字匹配身份。静态原型来源无ID时，仅在本地样本构建中以同环境精确名称多重集合和一致类型核对，不能按相似名字、数组位置或其他环境样本猜身份；此构建手段不进入生产。来源名单已变化时刷新整个环境行的总览快照，状态、名单和汇总取同一批，并保留前后证据。账号明细只补固定类型，不能用其不同时间的在线状态覆盖总览。

原型快照与各环境类型证据独立保存，少量历史账号的类型以用户明确确认为依据，不能描述成全部由当日线上明细采得。原型使用本地完整快照；公开投影仅遮罩名称内11位手机号，保留普通名称、数量、类型和重名关系。原始采集、账号凭据和连接配置不发布。

有账号却缺少合法类型，或计数格式非法时，不渲染不完整分组。来源汇总与名单条数不一致时，保留来源汇总并在内部记录诊断，不能静默配平或删账号。初次读取失败沿用“页面读取失败 / 请重新加载本地页面。 / 重试”；已经成功展示后重绘失败保留原正确内容。该路由由专用组件承接，失败不能退回旧通用演示数据，也不能露出别的环境样本。

## 保留的交互

环境名称排序保持原始→升序→降序→原始，同值排序稳定。微信与代理页签分别保留滚动位置；冻结表头保持列对齐，长名单的组标题停留在表头下方且不越过本组。长账号名可换行，不用截断隐藏姓名。排序、页签及滚动保留键盘和焦点行为。

代理页签展示原代理卡片和在线/掉线状态，本次快照118张。118仅为本轮快照条数；分类功能不改变代理业务，不增加刷新、编辑或真实账号操作。2026-09-27“代理页尚未采集”的历史边界已由本轮完整快照替代，不能继续用旧提示作为当前bzds页实现。
