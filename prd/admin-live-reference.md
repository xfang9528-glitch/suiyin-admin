## 用户结果与范围

管理者和评审者进入对应租户后，可按真实页面的结构检查筛选、表格、配置和指定操作，并识别数据来源。不能以通用列表、其他租户的人员或推断的展开内容冒充当前租户实站。

范围为十五租户：佰智德三、锦帛美学、萌爪、诚如风险管理事务所、厚全鸡蛋、柚子烘焙；瑞熙小刘、小温、小周；艺星成都、深圳、北京、广州、杭州、嘉兴。当前导航库存为 **802 个租户页面入口、89 种路由**。其中783个为源环境队列，741个可见页有有效DOM与截图，42个按源隐藏；另有13个既有AI费用原型扩展，以及6个现有艺星回访规则合成入口，不将后者写成实站采集。截图排除项、碎银私域和不可访问环境不新增纳入。各租户保留自己的可用入口、权限和独立显示配置；菜单表和侧栏按068共用有效完整树。平台allMenu提供默认顺序和归属，租户明确调过的同级列表及被移动项父级优先；平台当前祖先链隐藏/删除和既有权限始终约束可见导航。

## 艺星回访规则

行为合同：[071@1.2.0](../docs/sdd/SPEC-SUIYIN-ADMIN-071/1.2.0/README.md)，对应R001–R015。管理者先配置每天应找哪些好友，再确定每日筛选时间，减少重复组合相同条件。深圳、成都、北京、广州、杭州、嘉兴六个现有艺星租户各自提供「聊天管理 → 回访规则」（`revisitRules`）；不同渠道可分别配置规则。此前撤回的全系统租户扩展、移到群发及新增群发规则仍不实施；本次六艺星范围是后续明确授权。

|---|---|---|
| 深圳艺星 | `yestar-sz` | `group-10` |
| 成都艺星 | `yestar` | `group-9` |
| 北京艺星 | `yestar-bj` | `group-9` |
| 广州艺星 | `yestar-gz` | `group-10` |

六租户普通菜单 `menu` 各登记一次同一路由，德三 `allMenu` 复用唯一平台定义；平台定义存在不代表其他租户获得入口。新增五店按各自已发布菜单revision基线迁移，保留本地删除、隐藏、改名与排序；深圳既有菜单状态不重新激活。

| 层级 | 配置及行为 |
|---|---|
| 整条规则共用 | 名称、回访目的、账号群组/账号、回访基准日期、每日筛选时间、启停；保存与启用分开，新建默认未启用 |
| 规则内时间节点 | 基准后第N天、可选说明、独立选中与排除；支持增改删，至少一个，非负整数天数不能重复并按天数排序 |
| 节点条件复制 | 目标选择同规则来源节点；仅复制选中/排除，目标天数、身份、说明和共享设置不变；有旧条件时明确确认替换，可取消，复制后互不联动 |

第3、5、7天在列表中属于一条“添加好友后回访”规则。1.0.0的“每个节点独立成为顶层规则、整套规则复制”已被本版替代，只作历史；节点不是依次完成的任务流程，前一节点被排除或未完成不自动取消后续节点。第N天只在节点填写；日期维度仍可追加固定日期、相对日期或区间等限制，并与节点到期同时满足。

两侧维度完整继承已核对的艺星群发合同。六租户的账号、人员、地区、好友及规则分别创建；新增五店使用明确标识的独立合成示例，不把深圳实体或参考页内容当作本店实采目录。深圳保留既有样本与稳定ID：

| 维度组 | 选中与排除共有的21项 |
|---|---|
| 账号范围（1项） | 所在账号；规则层先确定共有范围，节点条件只能进一步缩小 |
| 等级与需求（5项） | 等级、等级(AI)、第一需求(AI)、第二需求(AI)、会员等级 |
| 基础资料与归属（5项） | 有电话、状态、地区、开发人、客服经理 |
| 日期（5项） | 末次咨询日期、添加日期、建档日期、未次预约日期、末次回访日期 |
| 画像与推荐（5项） | 建议改善、用户特征、推荐设备/材料、推荐医生、喜好风格 |

排除另含对方发过消息、我方发过消息、双方发过消息、新加好友、和工作号同在至少一个群，共26项。“未次预约日期”保留来源拼写，未改字段含义；状态仍为正常/异常，AI需求不等于已购产品，产品映射待确认。

账号群组就是渠道归属，不是另一个员工部门。群组与指定账号取并集；搜索与全选仅影响当前结果并保留其他已选项。要挑组内部分账号，先取消整个群组。到期节点的选中条件全部满足，同一字段多值取任一；排除命中任一即排除。深圳示例以我方近2天、对方近2天两项OR表达“任一方近期联系就跳过”，不能用要求两边都发过的“双方发过消息”替代；聊天不会重置添加日期锚点。第0天、48小时、计入的消息来源继续作为已标注的演示口径，未声称生产定案。

所有变更先进入草稿，取消保持已存规则不变，保存失败保留草稿供重试；成功保存整条规则后生效，已启用规则从下一次计划时点使用新配置，不补跑。0人可保存；失效范围、缺失数据及读取失败不能降格为0。试算以固定合成样本显示到期节点、应回访、已排除、未入选和无法判断及理由。

本地v2按 `admin-revisit-rules:v2:<tenant>` 保存规则与节点结构；QA使用独立前缀，切换租户不串读账号或规则。深圳原API、稳定ID、v1/v2键与原有用户规则保持兼容，新增租户不从深圳存储初始化；各自旧v1独立规则只读保留。发现旧数据时由使用者明确开始新版示例或逐条导入未启用草稿；只有唯一明确的日期“第N天”条件可无损转为基准与节点，其余筛选保留，歧义时说明原因，不自动合并。损坏数据不得静默覆盖。

销售可见合同为“应回访好友集合 ∩ 当前销售有接待权限的账号”；无账号接待权限就不能看到其好友，失去权限后也不能凭历史生成结果继续访问，多名有权销售均可见。当前交付管理页和该权限合同；PC名单界面、真实调度、权限服务、共享数据库、发送、执行质检和完成状态协作仍未实施。

## 销售变声统计

行为合同：[052@1.2.0](../docs/sdd/SPEC-SUIYIN-ADMIN-052/1.2.0/spec.md)。全部登记租户在「数据展示」拥有销售变声统计菜单定义，位置在销售使用统计附近；可见性继续受既有父级及权限配置约束，不自动开通变声账号。

- 日期与部门筛选继续复用销售使用统计：统计时间、单日/范围分段、对应日期输入和日历、今天/昨天/前天、部门、搜索/重置/导出；字段顺序、颜色、图标、尺寸、间距、焦点和取消反馈一致。单日只显示一个日期，范围显示起止日期；范围切回单日取开始日并将起止归为同日。
- 本轮补回来源已见的销售姓名框；姓名按本地包含匹配筛选，重名销售仍按稳定身份区分。模式和日期、部门、姓名编辑只改草稿，搜索才提交；快捷日按 Asia/Shanghai 运行当日计算，立即查询并保留当前模式。重置回单日、今天、全部授权部门及默认排序并立即查询。非法日期不覆盖旧结果，日历 Escape 或外部点击取消不提交。
- 表格展示序号、销售、部门、变声使用次数；次数数值排序，默认每页 20 条，导出包含全部筛选结果。
- 租户内独立任务首次成功生成计 1；重复成功回调、同任务重试不重复计，失败、取消录音和试听不计；无需等待消息发送成功。
- 以首次成功自然日、发起销售稳定身份及当时部门归属汇总，多工作账号归同一销售；不按显示名合并，不因转组改写历史。
- 有效零次数、无匹配销售、加载、失败重试和无权限分别表达。页面全部使用有来源说明的合成事件，不表示真实使用量。

**DR-095**：今后「数据展示」新增二级菜单，同次必须增加对应租户菜单管理项和已有平台定义。稳定身份、名称、路由和默认父级一致；隐藏后仍在完整库存可恢复。普通menu按068的拖动顺序、归属、显示配置联动同租户侧栏，平台allMenu按060提供全部租户的默认规则；068的明确局部覆盖优先，平台隐藏/删除及已有页面和权限边界保持有效。

## 拉新记录与消息占比
